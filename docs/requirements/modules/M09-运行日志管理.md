## 1. 模块概述

运行日志管理用于在排障场景下将 OMS 各服务的运行日志按范围打包收集，供业务运维人员下载分析。模块解决排障时需逐个节点手工获取日志、耗时且容易遗漏的问题。上游依赖 M11 通用提供的任务中心能力，日志收集任务的排队、取消与历史查看等通用能力由任务中心承载。下游影响运维排障效率，缩短故障定位与日志获取时间。日志包在收集完成后保存于 OMS 本地，由业务运维人员**在页面直接下载压缩包**，**不对接外部 SFTP 文件服务器**，故本模块无关键外部系统依赖。

| 项 | 内容 |
| --- | --- |
| 模块定位 | OMS 运行日志的按需打包收集与下载出口 |
| 上游依赖 | M11 通用（任务中心承载日志收集任务） |
| 下游影响 | 运维排障效率：缩短故障定位与日志获取时间 |
| 关键外部系统 | 无（日志包在页面直接下载，不对接外部文件服务器） |

### 3.1 FR-RTLOG-001 一键日志收集

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-RTLOG-001 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望使用预置的默认节点范围与默认时间范围一键发起日志收集，以便在紧急排障时无需任何选择即可立即取到常用范围的运行日志。

**③ 前置条件与触发方式**

- 前置条件：OMS 各服务运行正常且可被收集；系统已配置默认节点范围与默认时间范围；操作者具备日志收集权限
- 触发方式：页面入口（运行日志管理页面的「一键日志收集」按钮）

**④ 主流程**

1. 操作者进入运行日志管理页面
2. 操作者点击一键日志收集，不选择任何参数
3. 系统按预置的默认节点范围与默认时间范围创建日志收集任务
4. 系统提示任务已发起，并展示任务标识与进度入口
5. 收集完成后，系统提示日志包可下载

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 一键发起 | 使用系统预置参数，操作者不选择节点范围与时间范围 | FR-RTLOG-002 |
| 一键信息收集的内容边界 | 具体清单**由实际软件的架构决定**（系统状态、关键配置、运行日志的采集项由架构确定）；页面不固化清单，告知文案固定为「**系统状态 + 关键配置 + 48 小时内运行日志**」 | OI-M09-002 |
| 默认参数未配置 | 拒绝发起，并提示需先完成默认参数配置 | 无 |
| 操作者重复点击 | 避免重复创建参数相同的收集任务 | 无 |
| 收集过程中部分节点不可达 | 记录该情况，并在任务结果中给出说明 | FR-RTLOG-003 |
| 发起成功后 | 任务交由任务中心排队执行，排队与取消能力不在本分册定义 | 无 |
| 操作者无日志收集权限 | 拒绝发起 | FR-PERM-001 |

**待确认**

无

### 3.2 FR-RTLOG-002 发起日志收集

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-RTLOG-002 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望自定义节点范围、时间范围与日志类型后发起日志收集，以便针对特定故障范围精确获取所需的运行日志。

**③ 前置条件与触发方式**

- 前置条件：OMS 各服务运行正常且可被收集；可收集的节点与日志类型已可用；操作者具备日志收集权限
- 触发方式：页面入口（运行日志管理页面的「发起日志收集」入口）

**④ 主流程**

1. 操作者进入发起日志收集页面
2. 操作者选择节点范围、时间范围与日志类型
3. 系统确认所选范围有效且处于可收集范围内
4. 操作者确认后，系统创建日志收集任务
5. 系统提示任务已发起，并展示任务标识与进度入口

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 未选择节点范围或时间范围 | 拒绝发起，并提示必填项 | 无 |
| 起始时间晚于或等于终止时间 | 拒绝发起，并提示「起始时间需早于终止时间」 | 无 |
| 「自定义时间」的跨度 | **不设跨度上限**：起始时间到终止时间的跨度可以超过 48 小时；2-48 小时的约束只作用于「指定时间」 | OI-M09-001 |
| 所选时间范围超出可收集范围 | 拒绝发起，并提示可收集的时间范围 | 无 |
| 所选节点全部不可达 | 拒绝发起，并提示节点当前不可用 | 无 |
| 所选节点范围或时间范围过大 | 提示预计耗时较长，建议缩小范围 | FR-RTLOG-003 |
| 所选日志类型不可用 | 拒绝发起，并提示可选的日志类型 | 无 |
| 发起成功后 | 任务交由任务中心排队执行，通用任务能力不在本分册定义 | 无 |
| 操作者无日志收集权限 | 拒绝发起 | FR-PERM-001 |

**待确认**

无

### 3.3 FR-RTLOG-003 收集进度查询

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-RTLOG-003 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望查看日志收集任务的进度与状态，以便判断何时可以下载日志包，并在失败时了解失败原因。

**③ 前置条件与触发方式**

- 前置条件：已发起至少一次日志收集任务；操作者具备查看日志收集任务的权限
- 触发方式：页面入口（运行日志管理页面的任务列表与任务详情）；事件（任务状态变化时自动更新进度）

**④ 主流程**

1. 操作者进入运行日志管理页面查看任务列表
2. 系统展示各任务的当前状态与进度
3. 操作者打开某一任务查看详情
4. 系统展示进度、状态与已耗时
5. 任务失败时，系统展示失败原因及受影响的节点范围

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 任务状态分类 | 至少区分进行中、成功、失败 | 无 |
| 任务进行中 | 展示当前进度，并在状态变化时更新 | 无 |
| 任务失败 | 给出可理解的失败原因，便于操作者决定是否重新发起 | 无 |
| 部分节点收集失败、其余成功 | 在结果中说明失败节点，避免被误认为收集完整 | FR-RTLOG-001 |
| 任务处于排队等待中 | 展示等待状态；排队、取消与历史查看等通用能力由任务中心提供 | 无 |
| 任务历史记录超出保留范围 | 按任务中心的保留要求处理 | 无 |

**待确认**

无

### 3.4 FR-RTLOG-004 下载日志包

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-RTLOG-004 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望下载已成功完成的日志包，以便在本地分析故障原因，同时保证下载行为可追溯。

**③ 前置条件与触发方式**

- 前置条件：日志收集任务已成功完成且日志包仍在保留期内；操作者具备日志包下载权限
- 触发方式：页面入口（任务列表或任务详情的下载入口）

**④ 主流程**

1. 操作者在任务列表或任务详情中查看已成功完成的任务
2. 操作者点击下载日志包
3. 系统确认任务已成功完成且日志包仍可用
4. 系统提供日志包下载
5. 系统将本次下载行为留痕，可被追溯

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 任务未成功完成 | 不提供下载，并提示当前任务状态 | 无 |
| 日志包已过保留期并被清理 | 不提供下载，并提示日志包已清理 | 无 |
| 下载行为本身 | 留痕可查，包含下载人与下载时间 | FR-OPLOG-001 |
| 同一日志包被多次下载 | 每次下载分别留痕 | 无 |
| 日志包的存放与获取方式 | 收集完成后保存于 OMS 本地，由业务运维人员**在页面直接下载压缩包**；**不投递至外部 SFTP 文件服务器**，本模块不定义对外投递能力 | 无 |
| 操作者无下载权限 | 拒绝下载 | FR-PERM-001 |

**待确认**

无
