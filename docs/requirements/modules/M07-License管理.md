## 1. 模块概述

License 管理负责 OMS 授权凭证的全生命周期：生成并展示系统唯一序列号（ESN）、导入与激活产品方签发的 License 文件、展示授权信息（加载日期、截止日期、容量与消耗）、吊销授权、查询失效信息，以及在授权临近到期或容量接近上限时产生告警。它解决授权状态不透明——运维无法判断当前授权是否有效、容量是否够用、何时需要续期——的问题，把授权凭证与容量约束沉淀为可查看、可追溯的统一能力。容量计量项在本模块做**通配处理**：不内置固定计量项清单，计量项由 License 文件按约定格式声明，具体计量口径依上层业务而定。本模块不依赖其他 OMS 模块，但容量消耗数据由上层业务模块按约定提供。**OMS 是上层业务的底座**：本模块只如实反映授权状态与消耗，**OMS 自身功能不因未授权、已过期或已吊销而受限**，是否限制由上层业务依据授权状态自行决定；下游影响上层业务模块（依据授权状态自行实施限制）与 M17 告警管理（到期与容量告警的展示与通知）。

| 项 | 内容 |
| --- | --- |
| 模块定位 | OMS 授权凭证（License）的管理入口：ESN 获取、导入与激活、信息展示、吊销与失效追溯、计量项**通配**的消耗计算与到期告警 |
| 上游依赖 | 容量计量项的消耗数据由上层业务模块按约定格式提供（本模块不内置计量项清单）；License 文件由产品方线下签发后交付 |
| 下游影响 | 上层业务模块（依据 License 状态自行实施相应限制）；M17 告警管理（到期与容量告警的展示、通知与清除）；**OMS 自身功能不因授权状态受限** |
| 关键外部系统 | 上层业务模块（提供计量项与消耗数据，并依据授权状态自行限制）；License 文件由产品方线下签发并交付，系统不联网校验 |

### 3.1 FR-LIC-001 生成 ESN、查询 ESN

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-LIC-001 | V1.0 |

**② 需求描述**

作为系统管理员，我希望查看并导出本系统的 ESN，以便向产品方申请与本系统匹配的 License 文件。

**③ 前置条件与触发方式**

- 前置条件：OMS 已完成安装部署并可正常运行；操作者具备 License 查看权限
- 触发方式：页面入口——License 管理页面的 ESN 展示、复制与导出入口

**④ 主流程**

1. 操作者进入 License 管理页面
2. 系统展示本系统的 ESN（系统唯一序列号）
3. 操作者复制或导出 ESN，用于向产品方申请 License 文件
4. 系统对 ESN 的展示与导出动作留痕

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 系统安装部署完成 | 生成唯一 ESN 并固化保存，作为本系统的授权对象标识 | 无 |
| ESN 的稳定性 | 安装部署时生成并固化，**安装后不再变化**：不随版本升级、重装、恢复备份或迁移部署环境而改变；同一环境多次查询返回同一 ESN | 无 |
| ESN 尚未生成或读取失败 | 明确提示失败原因，不得展示空白、临时值或他人 ESN | 无 |
| ESN 的展示与导出 | 留痕可查，包含操作者与时间 | FR-COM-003 |
| 操作者无 License 查看权限 | 拒绝查看与导出 | FR-PERM-001 |

**待确认**

无

### 3.2 FR-LIC-002 上传 License 文件

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-LIC-002 | V1.0 |

**② 需求描述**

作为系统管理员，我希望导入产品方签发的 License 文件，以便把授权凭证纳入系统并进入可激活状态。

**③ 前置条件与触发方式**

- 前置条件：已获取与当前 ESN 匹配的 License 文件；操作者具备 License 导入权限；当前无正在进行的导入操作
- 触发方式：页面入口——License 管理页面的「导入 License」入口

**④ 主流程**

1. 操作者进入 License 管理页面，选择导入 License
2. 系统提示需上传与当前 ESN 匹配的 License 文件
3. 操作者选择并上传文件
4. 系统校验文件格式、完整性、签名与 ESN 匹配性
5. 校验通过后系统保存该文件并置为待激活状态，展示其授权对象、有效期与容量概要
6. 系统记录本次导入动作与结果

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 文件格式或结构不合规 | 拒绝导入并给出明确原因，不留下无效授权记录 | 无 |
| 文件与当前 ESN 不匹配 | 拒绝导入并提示 ESN 不匹配，不允许通过任何方式使用他机 License | FR-LIC-001 |
| 文件完整性或签名校验失败 | 拒绝导入并提示文件可能被篡改 | 无 |
| 重复导入同一 License 文件 | 提示该 License 已存在，不产生重复授权记录 | FR-LIC-003 |
| 导入的是已吊销或已过期的 License | 允许留存记录但明确标注其失效状态，不得激活 | FR-LIC-005、FR-LIC-006 |
| 导入动作 | 留痕，记录操作者、时间、文件名与校验结果 | FR-COM-003 |
| 操作者无导入权限 | 拒绝导入 | FR-PERM-001 |

**待确认**

### 3.3 FR-LIC-003 激活 License

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-LIC-003 | V1.0 |

**② 需求描述**

作为系统管理员，我希望激活已导入的 License，使授权容量与有效期正式生效，并在替换授权时明确旧授权的去向。

**③ 前置条件与触发方式**

- 前置条件：License 文件已导入且校验通过；处于待激活状态，或需要以新授权替换当前生效授权；操作者具备激活权限
- 触发方式：页面入口——License 列表中的「激活」入口；事件——导入成功后由操作者发起激活

**④ 主流程**

1. 操作者选择待激活的 License 记录并发起激活
2. 系统再次校验文件有效性、有效期与 ESN 匹配性
3. 系统按文件内容写入授权信息：授权对象、容量、有效期，并记录**加载日期**与**截止日期**
4. 系统将 License 置为已激活，授权容量与有效期即时生效
5. 系统提示激活成功，并展示授权概要与生效时间
6. 系统记录本次激活动作

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 已有生效中的 License 时再次激活 | 提示将替换现有授权及其容量与有效期变化，经操作者确认后执行，原授权记录保留可追溯 | FR-LIC-004 |
| License 已过期 | 拒绝激活，不得通过激活动作绕过有效期 | FR-LIC-006 |
| License 已被吊销 | 拒绝激活并说明该授权已吊销 | FR-LIC-005 |
| 激活过程中失败 | 保持原有授权状态不变，不得出现半激活或容量数据不一致 | 无 |
| 激活前系统时间被回拨 | 以可信时间基准判定有效期，时间回拨不得延长授权，并记录异常 | 无 |
| 加载日期与截止日期 | 加载日期取本次激活生效时间，截止日期按 License 文件给定的有效期计算，二者均须在信息查询中可见 | FR-LIC-004 |
| 激活动作 | 留痕，记录操作者、时间、License 标识与结果，可供审计 | FR-COM-003 |
| 操作者无激活权限 | 拒绝激活 | FR-PERM-001 |

**待确认**

无

### 3.4 FR-LIC-004 查询 License 信息

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-LIC-004 | V1.0 |

**② 需求描述**

作为系统管理员，我希望查看当前 License 的授权信息——加载日期、截止日期、容量与消耗、授权状态——以便判断授权是否满足当前使用规模、是否需要提前申请续期或扩容。

**③ 前置条件与触发方式**

- 前置条件：已激活有效 License，或系统中存在历史授权记录；操作者具备 License 查看权限
- 触发方式：页面入口——License 管理页面的授权信息与历史授权入口

**④ 主流程**

1. 操作者进入 License 信息页面
2. 系统展示当前授权概要：授权对象（ESN 与 License 标识）、**加载日期**、**截止日期**、剩余有效期与授权状态
3. 系统展示**容量信息**：各计量项的授权总量、已消耗量与剩余量，并标注统计时间
4. 操作者查看历史授权记录与失效情况
5. 页面实时反映授权状态与消耗的最新变化

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 未导入或未激活 License | 明确展示「未授权」状态与导入引导，不展示空白或错误的容量数据 | FR-LIC-002 |
| 加载日期 | 展示本次授权实际生效（激活）的日期，可追溯到激活动作 | FR-LIC-003 |
| 截止日期 | 按 License 文件给定的有效期展示；临近截止时按告警规则提示 | FR-LIC-008 |
| 容量信息 | 按 License 文件中声明的计量项**通用展示**授权总量、已消耗量与剩余量，本模块不预置固定计量项；消耗计算见 FR-LIC-007 | FR-LIC-007 |
| 授权状态 | 至少区分待激活、已激活、即将到期、已过期、已吊销 | FR-LIC-003、FR-LIC-005 |
| License 状态对 OMS 自身的影响 | **OMS 是上层业务的底座，其自身功能不因未授权、已过期或已吊销而受限**（不据此拒绝登录或限制功能）；本模块只如实反映授权状态与消耗，由上层业务依据该状态自行实施相应限制 | 无 |
| 已过期或已吊销的授权 | 以失效状态展示，并可在失效信息查询中追溯原因与时间 | FR-LIC-006 |
| 操作者无 License 查看权限 | 拒绝查看 | FR-PERM-001 |

**待确认**

### 3.5 FR-LIC-005 吊销 License

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-LIC-005 | V1.0 |

**② 需求描述**

作为系统管理员，我希望在授权需要作废时吊销当前 License，以便停止其授权效力、明确影响范围并保留可追溯的记录。

**③ 前置条件与触发方式**

- 前置条件：存在已激活的 License；操作者具备 License 吊销权限；已明确吊销原因（如更换授权对象、试用结束、合规要求）
- 触发方式：页面入口——License 信息页的「吊销」入口；事件——收到授权作废要求时执行

**④ 主流程**

1. 操作者选择当前生效的 License 并发起吊销
2. 系统展示吊销后授权容量与有效期将不再生效的影响提示
3. 操作者填写吊销原因并二次确认
4. 系统将该 License 置为已吊销，授权容量与有效期停止生效
5. 系统记录吊销时间、操作者与原因，并转入失效信息
6. 系统提示对当前使用规模的可能影响

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 未填写吊销原因 | 吊销不成立，须补充原因后再次确认 | 无 |
| 吊销后当前使用规模超出授权容量 | 明确提示超限状态与影响范围；**OMS 自身功能不因吊销受限**，由上层业务依据授权状态自行处置 | FR-LIC-007 |
| 已吊销的 License 再次导入或激活 | 拒绝激活，并说明该授权已被吊销 | FR-LIC-003 |
| 吊销动作 | 留痕且不可被修改，可供审计管理员审计 | FR-COM-003 |
| 伪造或绕过吊销状态 | 不提供本地开关把已吊销状态改为有效，授权状态不得被本地配置篡改 | 无 |
| 操作者无 License 吊销权限 | 拒绝吊销 | FR-PERM-001 |

### 3.7 FR-LIC-007 计算 License 消耗

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-LIC-007 | V1.0 |

**② 需求描述**

作为系统管理员，我希望系统按 License 文件中声明的计量项**通用地**计算已消耗量与剩余量，以便在计量项依上层业务而定、可能随业务扩展而变化的情况下，仍能判断是否接近上限、是否需要在新增对象前先扩容。

**③ 前置条件与触发方式**

- 前置条件：License 已激活且其计量项已按约定格式声明；上层业务模块可按约定格式提供计量项的消耗数据
- 触发方式：事件——计入消耗的对象新增、删除或状态变化时重新计算；页面入口——查看消耗明细；定时任务——周期性汇总

**④ 主流程**

1. 系统读取 License 文件中按约定格式声明的计量项（标识、名称、授权数量、单位等）
2. 上层业务模块按约定格式登记其计量项的消耗变化（新增、删除或状态变化）
3. 系统按计量项累计已消耗量并计算剩余量
4. 页面展示各计量项的消耗明细、占比与统计时间
5. 消耗接近或达到授权数量时，系统按告警规则提示，并给出超限状态供上层业务自行处置
6. 系统记录消耗变化与超限状态

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 计量项的处理方式 | **通配处理**：不内置固定计量项清单，完全按 License 文件中声明的计量项进行解析、展示与校验；具体计量口径依上层业务而定 | 无 |
| 计量项的声明格式 | 按与产品方约定的格式导入（计量项标识、名称、授权数量、单位等），格式细节见《OMS 接口设计文档》 | 无 |
| 业务模块登记了 License 未声明的计量项 | 记录并提示该项不在授权范围内，不纳入授权容量校验与展示 | 无 |
| 消耗达到授权数量上限 | 对该计量项给出**超限状态**并记录；**是否限制由上层业务依据 License 状态自行决定**，OMS 不代为限制自身功能 | 无 |
| 已消耗量超过授权容量（如吊销或降配后） | 明确提示超限状态与影响范围，供上层业务与运维处置；OMS 自身功能不受限 | FR-LIC-005 |
| 计入消耗的对象被删除 | 相应释放消耗量并更新剩余量，保留操作留痕 | FR-COM-003 |

### 3.8 FR-LIC-008 定时 License 告警检查

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-LIC-008 | V1.0 |

**② 需求描述**

作为系统管理员，我希望系统定时检查 License 的有效期与消耗情况，并在临近到期或容量接近上限时产生告警，以便提前申请续期或扩容。

**③ 前置条件与触发方式**

- 前置条件：License 已激活；告警检查周期与阈值（到期前天数、容量占比）已由后台配置提供；M17 告警管理可用
- 触发方式：定时任务——按周期执行检查；事件——License 状态变化时触发检查

**④ 主流程**

1. 系统按配置周期检查 License 的截止日期与各计量项的消耗占比
2. 命中阈值时，系统产生告警并通知责任人
3. 告警内容包含 License 标识、截止日期、剩余天数或消耗占比
4. 在告警未清除前重复命中同一条件时，按 M17 去重规则处理，不重复展示，仅更新最近发生时间与次数
5. 续期激活成功或消耗回落到阈值以下时，系统**主动向 M17 告警管理上报清除信息**，使对应告警清除
6. 系统记录检查与告警动作

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 授权临近截止日期 | 按到期前阈值产生告警；随剩余天数减少保持该告警未清除，不重复产生新告警 | FR-ALM-001 |
| 容量接近上限 | 按消耗占比阈值产生告警 | FR-LIC-007 |
| 授权已过期 | 产生告警并按过期后的行为规则处理 | FR-LIC-006 |
| 异常恢复（续期激活成功或消耗回落） | **主动向 M17 告警管理上报清除信息**，使对应告警清除；不得依赖超时自动消失 | FR-ALM-005 |
| 检查周期与阈值的配置方式 | 由**后台配置**提供（如 configmap），**不开放界面修改**；调整后自下一个检查周期生效 | 无 |
| 后台未配置检查周期或阈值 | 使用内置默认值执行并记录，不得出现无告警的静默状态 | 无 |
| 重复命中同一告警条件 | 按 M17 规则判定为重复告警，不重复展示，更新最近发生时间与次数 | FR-ALM-001 |
| 检查动作 | 留痕，可供查询与审计 | FR-COM-003 |
