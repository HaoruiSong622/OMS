## 1. 模块概述

角色管理是 OMS 授权体系的**能力来源层**，把分散的功能能力、菜单可见范围与可访问的资源类型打包成角色，再绑定到用户组，由用户组成员获得该角色的能力。**角色绑定用户组、不直接绑定账户**，从而实现粗粒度管理：调整用户组的角色绑定即可批量改变一组账户的权限。OMS 中的角色**全部为内置角色**：角色在开发阶段针对具体场景定义并随版本交付，并在开发阶段为每个角色赋予相应权限；系统运行期**暂不开放系统管理员自定义创建角色**，但架构上保留该扩展能力（见 FR-ROLE-001）。**系统管理员**在运行时的职责是把内置角色绑定到用户组或解除绑定——**角色的权限范围在开发阶段内置、运行时只读不可调整**；其中**三个内置用户组（系统管理员组 / 安全管理员组 / 审计管理员组）承载三权分立中的三个内置角色，其绑定关系由系统固化，不允许添加或移除绑定角色**。本模块上游依赖 M04 资源组与用户组管理（用户组是角色的绑定对象），下游影响 M16 权限控制（角色绑定结果经用户组决定权限判定结果）。与上层业务系统之间的角色配置同步不属于本模块能力，由 M16 权限控制承载。

| 项 | 内容 |
| --- | --- |
| 模块定位 | 内置角色的使用：运行时角色清单与权限范围均只读，只能将角色绑定到用户组（不直接绑定账户） |
| 上游依赖 | 角色本体及其权限由开发阶段内置并随版本交付，不来自运行时配置；M04 资源组与用户组管理提供用户组作为角色的绑定对象（账户不直接绑定角色） |
| 下游影响 | M16 权限控制依据「账户所属用户组绑定的角色」判定其可用的功能能力、可见菜单与可访问的资源类型；上层业务系统的角色配置同步依赖本模块的角色绑定结果 |
| 关键外部系统 | 上层业务系统（存在角色配置同步场景，但同步能力归 M16 权限控制的 FR-PERM-004，本模块不实现） |

### 3.1 FR-ROLE-001 内置角色注册

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-ROLE-001 | V1.0 |

**② 需求描述**

作为系统管理员，我希望 OMS 的角色清单及其权限由开发阶段内置、运行期暂不开放自定义创建角色的入口，以便角色来源与权限口径受控，同时架构上保留运行期自定义创建角色的扩展能力，便于后续按需开放。

**③ 前置条件与触发方式**

- 前置条件：该角色已在开发阶段随需求定义并随版本内置到 OMS；角色在系统初始化或版本升级时完成注册；操作者具备角色查看权限
- 触发方式：系统初始化事件；版本升级事件（系统不提供运行时的角色创建入口）

**④ 主流程**

1. 开发阶段按业务场景与职责划分定义角色，随版本交付
2. 系统在初始化或版本升级时将内置角色注册进授权体系，形成角色清单
3. 系统管理员在角色管理页面查看内置角色清单及其名称、分类与职责说明
4. 新注册角色的功能能力与菜单范围在开发阶段一并内置，随版本交付、运行时不提供调整入口
5. 系统管理员查看该角色的权限范围，并将其绑定到一个或多个用户组
6. 角色清单的变更随版本发布生效，运行时不可新增、改名或删除

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 运行期的角色创建入口 | 本期不开放，角色由开发阶段内置并随版本交付 | 无 |
| 运行期请求新增角色 | 本期不受理，请通过版本内置方式引入 | 无 |
| 运行期自定义创建角色的扩展性 | 架构上保留该能力；后续开放时不得要求重构角色—权限模型与既有用户组绑定关系 | 无 |
| 内置角色 | 运行时不允许删除、停用或改名 | 无 |
| 内置角色在开发阶段定义后的名称、职责与权限 | 同一版本内保持唯一，不允许重复定义 | 无 |
| 新注册的内置角色 | 其功能能力与菜单范围在开发阶段一并内置，运行时不可调整 | FR-ROLE-003 |
| 角色清单中的三权分立管理员角色 | 由系统预置，不允许删除或停用 | FR-ACC-001 |
| 需为新场景引入角色 | 由开发阶段新增内置角色并随版本发布，不在运行时创建 | 无 |
| 角色已内置但尚未授予任何账户 | 角色保留在清单中，不影响任何账户的登录与权限判定 | FR-ROLE-002 |
| 操作者无角色查看权限 | 拒绝访问角色清单 | FR-PERM-001 |

### 3.2 FR-ROLE-002 角色与用户组绑定

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-ROLE-002 | V1.0 |

**② 需求描述**

作为系统管理员，我希望把角色绑定到用户组，以便该组成员通过绑定关系获得角色对应的功能能力、可见菜单与可访问资源类型，并在职责变化时通过调整绑定关系批量回收权限。

**③ 前置条件与触发方式**

- 前置条件：目标用户组已存在且可用（由 M04 资源组与用户组管理维护）；被绑定的角色已内置且未被停用；操作者具备角色绑定权限
- 触发方式：角色管理页面的绑定用户组入口；用户组详情页的角色绑定入口

**④ 主流程**

1. 操作者在角色清单中选择目标角色，进入绑定用户组配置
2. 系统展示可绑定的用户组清单，并标注该角色当前已绑定的用户组
3. 操作者选择一个或多个用户组进行绑定，或解除已有绑定关系（**内置用户组的绑定关系由系统固化，不提供添加与移除入口**）
4. 系统校验绑定关系的合法性，并校验绑定后是否存在账户同时具备系统管理员与审计管理员能力
5. 系统保存绑定关系，相关用户组成员的权限随绑定结果生效；变更生效后相关成员的已登录会话被强制过期，须重新登录
6. 操作者可在角色详情与用户组详情中查看最新的绑定关系

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 目标用户组不存在或已停用 | 拒绝绑定并提示该用户组当前不可用 | 无 |
| 向账户直接绑定角色 | 不提供该能力，角色只绑定用户组；账户的权限经用户组传递 | 无 |
| 被绑定的角色未内置、已停用或已删除 | 拒绝绑定 | FR-ROLE-001 |
| 同一角色重复绑定同一用户组 | 保持绑定关系唯一，并提示该用户组已绑定 | 无 |
| **内置用户组**（系统管理员组 / 安全管理员组 / 审计管理员组） | **不允许添加或移除绑定角色**：绑定与解除入口均不可用并提示原因——三个内置用户组分别承载三权分立中的三个内置角色，其绑定由系统固化；其**关联资源组**（范围维度）仍可调整 | OI-M04-007 |
| 一个用户组绑定多个角色 | 允许，该组成员的能力为各角色权限的并集 | FR-PERM-001 |
| 绑定后存在账户同时具备系统管理员与审计管理员能力 | 拒绝绑定，违反三权分立互斥要求 | FR-ACC-001 |
| 绑定关系发生变更（绑定或解除绑定） | 即时生效：相关成员据此获得或不再拥有该角色对应的功能能力、可见菜单与可访问资源类型；其已登录会话被**强制过期**，须重新登录 | FR-PERM-001 |
| 绑定关系变更 | 须留痕，记录操作者、时间与影响的用户组与账户范围 | FR-OPLOG-001 |
| 角色的权限范围 | 由开发阶段内置，本模块不提供调整入口；可调整的只有角色与用户组的绑定关系 | FR-ROLE-003 |

### 3.3 FR-ROLE-003 角色权限范围查看

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-ROLE-003 | V1.0 |

**② 需求描述**

作为系统管理员，我希望查看每个内置角色对应的功能能力、菜单可见范围以及可访问的资源类型，以便在绑定用户组之前确认该角色实际会带来哪些权限，避免误绑定。

**③ 前置条件与触发方式**

- 前置条件：目标角色已内置并完成注册；该角色的权限范围已随版本内置；操作者具备角色查看权限
- 触发方式：角色管理页面的角色详情入口

**④ 主流程**

1. 操作者在角色清单中选择目标角色，进入角色详情
2. 系统按模块与菜单层级展示该角色对应的功能能力与菜单可见范围，并展示该角色可访问的资源类型
3. 系统展示该角色当前已绑定的用户组
4. 操作者据此评估该角色是否适合授予目标人员
5. 系统展示的权限范围与该角色实际生效的授权保持一致，且不提供修改入口

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 调整角色的权限范围 | 不提供该能力，权限范围由开发阶段内置并随版本交付 | 无 |
| 角色可访问的资源类型 | 由角色的权限范围决定；绑定该角色的用户组成员不具备某类资源能力时，无论该类资源归属哪个资源组都无法访问 | FR-RG-004 |
| 角色尚未授予任何账户 | 仍展示其权限范围，便于授权前评估 | 无 |
| 展示的权限范围与该角色实际生效的授权 | 必须一致，不允许出现展示与实际不符 | FR-PERM-001 |
| 角色权限范围随版本发生变更 | 以当前版本内置的范围为准，变更随版本发布生效 | 无 |
| 三个管理员角色 | 不特殊处理，其权限范围与其他角色一样在开发阶段内置且不可调整 | FR-ACC-001 |
| 操作者无角色查看权限 | 拒绝查看角色详情 | FR-PERM-001 |

**待确认**
