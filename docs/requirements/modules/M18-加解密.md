## 1. 模块概述

加解密模块是 OMS 的**内部基础能力**，**本身不是对外功能，也不提供独立的页面入口**。它把 OMS 所依赖的加解密组件 SCC 封装为统一的加解密能力，使用场景有两类：一是 OMS 内部对**证书密钥**等敏感数据执行加解密；二是**向上层业务提供加解密调用接口**，供上层业务在自身的加解密场景中使用。OMS 自身不实现密码算法，敏感信息的保护能力完全由该模块统一提供，各模块不再各自处理密码相关工作。**本模块只提供加解密能力，不提供签名与令牌（ticket）能力**；令牌的防伪、有效期管理等由相应能力负责，不属于本模块范围。由于不自行实现算法，SCC 加解密组件不可用时，依赖加解密能力的功能必须明确失败，不得降级为明文处理。本模块同时约束谁有权调用加解密能力、哪些调用方可以解密已有数据，以及密钥的生成与轮换由授权角色管理。

| 项 | 内容 |
| --- | --- |
| 模块定位 | OMS 内部的统一加解密基础能力（**非对外功能、无独立页面入口**）：为证书密钥等敏感数据提供加解密，并向上层业务提供加解密调用接口 |
| 上游依赖 | 无；密码算法由外部 SCC 加解密组件提供，OMS 不自行实现 |
| 下游影响 | OMS 内部需要保护敏感数据的模块（主要场景为**证书密钥**的加解密）；上层业务系统（通过调用接口在自身场景中使用加解密能力） |
| 关键外部系统 | SCC 加解密组件；上层业务系统（加解密能力的调用方） |

### 3.1 FR-CRYP-001 SCC 加解密

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-CRYP-001 | V1.0 |

**② 需求描述**

作为 OMS 内部需要保护敏感数据的模块（主要场景为证书密钥），我希望调用统一的加解密能力完成加解密，以便在无需自行实现密码处理的前提下安全地保存与还原敏感数据。

**③ 前置条件与触发方式**

- 前置条件：调用方（OMS 内部模块）已被授权使用统一加解密能力；调用方与所处理敏感数据的授权范围已配置；SCC 加解密组件可用
- 触发方式：事件（内部模块在处理证书密钥等敏感数据时发起加解密请求）；密钥管理配置入口（授权角色发起密钥生成与轮换）

**④ 主流程**

1. 授权角色完成调用方授权范围与密钥管理的配置
2. 内部模块在处理证书密钥等敏感数据时发起加密请求，系统校验调用方身份与授权范围
3. 系统通过 SCC 加解密组件完成加密，向调用方返回可用于存储的加密结果
4. 调用方保存加密结果；需要使用时再发起解密请求
5. 系统再次校验调用方的解密授权范围，仅向授权范围内的调用方还原明文
6. 系统留存加解密操作的相关记录，记录中不含明文
7. 授权角色按需发起密钥轮换，轮换期间业务处理不中断
8. 轮换完成后，系统保证既有加密数据仍可按授权范围正常解密

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 调用方未被授权使用加解密能力 | 拒绝该次加解密请求并留痕 | 无 |
| 本模块的能力边界 | 仅提供加解密能力，**不含签名与令牌能力**；ticket 等令牌的防伪与有效期管理不在本模块范围内 | 无 |
| 同一份明文在不同调用场景下的可解密范围 | 仅谁加密谁可解，或在授权范围内的调用方可解，范围之外的调用方无法还原明文 | 无 |
| 调用方请求解密超出自身授权范围的数据 | 拒绝解密并留痕 | 无 |
| 密钥的生成与轮换 | 仅授权角色可管理；轮换过程不中断业务，轮换完成后既有数据仍可正常解密 | 无 |
| 加解密失败 | 明确失败并留痕，不得降级为明文处理或返回未受保护的数据 | 无 |
| SCC 加解密组件不可用 | 依赖加解密能力的功能明确失败并提示，不得降级为明文处理 | 无 |
| 加解密过程中涉及的明文 | 明文不写入日志，也不出现在操作记录中 | 无 |
| 密钥不可用 | 拒绝加解密请求并提示由授权角色处理，不暴露敏感信息 | 无 |

**待确认**

无

### 3.2 FR-CRYP-002 上层业务加解密接口

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-CRYP-002 | V1.0 |

**② 需求描述**

作为上层业务系统，我希望调用 OMS 提供的加解密接口处理我自身场景中的敏感数据，以便复用 OMS 统一的密码能力，无需自行实现密码处理，也无需自行管理密钥。

**③ 前置条件与触发方式**

- 前置条件：调用方（上层业务系统）已完成接入登记并被授权使用加解密接口；其可加密与可解密的数据范围已配置；SCC 加解密组件可用
- 触发方式：接口调用——上层业务在自身的加解密场景中发起加密或解密请求

**④ 主流程**

1. 授权角色为上层业务配置调用授权与可解密范围
2. 上层业务在其自身场景中发起加密请求，系统校验调用方身份与授权范围
3. 系统通过 SCC 加解密组件完成加密，向调用方返回加密结果
4. 上层业务保存加密结果；需要使用时再发起解密请求
5. 系统再次校验调用方的解密授权，仅向授权范围内的调用方还原明文
6. 系统留存调用记录（调用方、时间、操作类型与结果），记录中不含明文

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 调用方未被授权或授权已失效 | 拒绝调用并留痕 | 无 |
| 调用方越权解密非授权范围的数据 | 拒绝解密并留痕 | FR-CRYP-001 |
| 调用凭据被冒用或调用来源不可信 | 拒绝调用并记录来源，提示安全管理员处置 | FR-PERM-001 |
| 调用超出已配置的调用约束（数据范围或用量） | 拒绝超出部分的调用并说明原因 | 无 |
| 加解密失败 | 明确失败并留痕，不得降级为明文处理或返回未受保护的数据 | 无 |
| SCC 加解密组件不可用 | 明确失败并提示，不得降级为明文处理 | FR-CRYP-001 |
| 调用过程中涉及的明文 | 明文不写入日志，也不出现在调用记录中 | 无 |
| 调用记录 | 留存调用方、时间、操作类型与结果，可供审计管理员审计 | FR-COM-003 |
