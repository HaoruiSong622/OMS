## 1. 模块概述

权限控制模块是 OMS 统一授权体系的运行时执行环节，负责把用户组绑定的角色能力及其关联的资源组范围落实到各个功能入口与后台能力上。它解决「授权结果与实际可访问范围不一致」的问题，避免越权访问与权限遗漏。权限必须同时在功能入口、菜单、操作按钮、后台能力调用四个层面生效，任何一层缺失都视为越权风险；任何未明确授权的能力默认拒绝，越权访问必须被拒绝且留痕。模块上游依赖 M03 角色管理与 M04 资源组与用户组管理，下游影响全部模块的功能可见性与可访问性。账户不直接持有角色，判定时须经「账户 → 用户组 → 角色 / 资源组」链路取得授权结果。关键外部系统为上层业务系统，用于角色与授权配置的同步。

| 项 | 内容 |
| --- | --- |
| 模块定位 | OMS 授权结果的运行时执行与校验，确保「已授权方可访问、未授权默认拒绝」 |
| 上游依赖 | M03 角色管理提供内置角色及其权限；M04 资源组与用户组管理提供用户组、用户组的角色绑定关系与资源组关联范围 |
| 下游影响 | 全部模块的菜单、操作按钮与后台能力的可见性、可访问性 |
| 关键外部系统 | 上层业务系统（角色与授权配置同步） |

### 3.1 FR-PERM-001 接口权限控制

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-PERM-001 | V1.0 |

**② 需求描述**

作为系统管理员，我希望任何后台能力的调用都必须先校验调用者是否被授权，以便越权访问在造成影响之前就被拒绝。

**③ 前置条件与触发方式**

- 前置条件：用户组的角色绑定与资源组关联均已配置并处于生效状态；调用者已完成身份认证且身份有效；被访问的资源已纳入资源组管理；权限校验能力处于启用状态
- 触发方式：事件——用户通过任一功能入口发起操作，或业务功能调用后台能力时触发

**④ 主流程**

1. 调用者通过功能入口或业务功能发起对后台能力的访问
2. 系统识别调用者身份、其所属用户组，以及该用户组绑定角色权限的**并集**与关联资源组范围的**并集**
3. 系统先校验该用户组绑定的角色是否具备该类资源的访问能力，再校验该资源是否落在该用户组关联的资源组范围内，并校验授权是否在有效期内
4. 授权通过时放行并进入业务处理；未授权时直接拒绝，不返回业务数据
5. 系统对越权访问尝试留下记录，供审计管理员审计
6. 系统将处理结果返回调用者

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 调用者未被明确授权 | 默认拒绝，不返回任何业务数据 | 无 |
| 调用者身份已失效或已注销 | 拒绝访问并引导重新认证 | 无 |
| 授权已过期、绑定关系已被解除或角色已停用 | 拒绝访问 | 无 |
| 发生越权访问尝试 | 拒绝访问并留痕，可供审计管理员事后审计 | 无 |
| 用户组绑定的角色具备该类资源的能力，但该资源不在其所属用户组关联的资源组范围内 | 拒绝访问（范围维度不满足） | FR-RG-004 |
| 资源在其所属用户组关联的资源组范围内，但其所属用户组绑定的角色均不具备该类资源的能力 | 拒绝访问（能力维度不满足） | FR-RG-004 |
| 账户经用户组组合后同时具备系统管理员与审计管理员的能力 | 该能力组合不得生效（三权分立互斥要求），须在角色绑定环节阻断 | FR-ACC-001 |
| 账户未归属任何用户组 | 不具备任何能力，默认拒绝访问 | FR-ROLE-002 |
| 已登录用户的权限被变更（角色绑定、用户组成员或资源组关联等授权关系变更） | 变更一经生效，系统立即将**受影响的已登录用户**（变更所涉用户组的成员，或所属用户组被迁移的账户）的会话置为过期，强制其重新登录；重新登录后按最新授权重新计算权限，不存在旧权限继续有效的情况；未受影响的在线用户不受影响 | FR-ROLE-002、FR-RG-003 |
| 功能入口、菜单、操作按钮、后台能力调用任一层缺少校验 | 视为越权风险，须在该层补齐校验后方可上线 | FR-PERM-002、FR-PERM-003 |

### 3.2 FR-PERM-002 菜单可见性控制

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-PERM-002 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望只看到自己有权访问的菜单，以便界面聚焦于我可用的功能。

**③ 前置条件与触发方式**

- 前置条件：用户组的角色绑定与资源组关联已生效；菜单已归属到相应资源组；用户已完成登录；菜单处于启用状态
- 触发方式：页面入口——用户登录后进入 OMS 主界面或任一功能页面时触发

**④ 主流程**

1. 用户登录 OMS 并进入主界面
2. 系统读取用户所属用户组绑定的角色权限与关联的资源组范围
3. 系统计算该用户可见的菜单范围
4. 系统仅展示已授权的菜单，未授权菜单不展示
5. 用户在可见菜单之间切换并进入对应功能页面
6. 受影响用户的权限发生变化后，其会话被强制过期，须重新登录；重新登录后系统按最新授权重新计算并展示菜单

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 用户对某菜单无权限 | 该菜单不可见，也不可通过非菜单途径进入 | FR-PERM-001 |
| 用户对所有菜单均无权限 | 展示无可用功能的明确提示，而非空白页面 | 无 |
| 子菜单有权限而上级菜单无权限 | 上级菜单按可达原则展示，其下仅展示已授权的子菜单 | 无 |
| 菜单可见但对应后台能力无权限 | 后台能力调用仍被拒绝，不以菜单可见作为授权依据 | FR-PERM-001 |
| 菜单被停用或下线 | 不再展示，已授权关系保留但不生效 | 无 |
| 受影响用户的权限被变更后 | 其会话被强制过期并引导重新登录，不得在原会话内继续停留；重新登录后按最新权限重新计算菜单，被收回的菜单不再展示 | FR-PERM-001 |
| 菜单归属的资源组被删除 | 该菜单不再对任何用户展示 | 无 |

**待确认**

### 3.3 FR-PERM-003 按钮可见性控制

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-PERM-003 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望看不到或无法操作我没有权限的按钮，以便避免误操作与越权尝试。

**③ 前置条件与触发方式**

- 前置条件：用户组的角色绑定与资源组关联已生效；操作项已与相应资源及权限关联；用户已进入包含操作按钮的功能页面
- 触发方式：页面入口——用户打开包含操作按钮的功能页面时触发

**④ 主流程**

1. 用户进入功能页面，系统读取用户当前有效的授权范围
2. 系统逐一判定页面内各操作按钮是否在授权范围内
3. 对无权限的按钮不展示或置为不可操作状态，并说明原因
4. 用户对可见且可操作的按钮发起操作，系统按后台能力校验结果决定是否执行
5. 操作完成后系统返回处理结果
6. 受影响用户的权限变化后，其会话被强制过期并引导重新登录；重新登录后页面按最新授权重新展示可操作按钮

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 用户对某操作按钮无权限 | 该按钮不可见或不可操作，不以可点击状态暴露 | FR-PERM-001 |
| 用户绕过页面直接发起同一操作 | 后台能力调用仍被拒绝并留痕 | FR-PERM-001 |
| 批量操作中部分数据无权限 | 仅处理有权限的数据，并明确提示被跳过的数据与原因 | 无 |
| 按钮依赖的前置条件不满足 | 按钮不可操作，并提示所缺条件 | 无 |
| 受影响用户的权限被变更后 | 其会话被强制过期并引导重新登录；重新登录后按最新权限重新展示可操作按钮，被收回的操作不可用 | FR-PERM-001 |
| 页面全部操作按钮均无权限 | 页面按只读方式展示，并提示无操作权限 | 无 |
| 按钮所属资源被删除或停用 | 对应按钮不再展示 | 无 |

### 3.4 FR-PERM-004 角色配置同步

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-PERM-004 | V1.0 |

**② 需求描述**

作为上层业务系统，我希望 OMS 把角色与授权配置同步给我，以便上层业务与 OMS 的权限口径保持一致。

**③ 前置条件与触发方式**

- 前置条件：同步范围已配置；同步目标已配置且可达；OMS 侧角色与授权配置已生效；同步功能处于启用状态
- 触发方式：定时任务——按配置的周期发起同步；事件——角色或授权配置发生变更时发起同步；页面入口——管理员手工触发同步

**④ 主流程**

1. 管理员配置需要同步的角色、用户组绑定关系与资源组关联范围，以及同步目标与同步周期
2. 到达同步周期或角色、授权配置发生变更时，系统发起同步
3. 系统按已配置的同步范围生成同步内容
4. 系统将同步内容送达上层业务系统
5. 系统记录并展示本次同步结果
6. 同步失败时系统按策略重试，重试仍失败则产生告警
7. 管理员查询同步结果与历史同步情况

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 同步范围变更 | 按最新配置的范围执行，已同步范围外的配置不再同步 | 无 |
| 同步失败 | 按策略自动重试，超过重试上限仍未成功则告警并保留待同步内容；后续同步恢复正常时主动向 M17 告警管理上报消除信息 | FR-ALM-005 |
| 同步目标不可达 | 保留待同步内容并提示管理员，恢复后继续同步 | 无 |
| 同步结果查询 | 可查询每次同步的范围、结果与失败原因 | 无 |
| 同步动作 | 全程留痕，可供审计管理员审计 | 无 |
| 同步内容部分成功 | 记录成功与失败明细，仅对失败部分重试，不重复同步已成功内容 | 无 |
| 角色或授权配置尚未生效 | 不纳入本次同步范围 | FR-PERM-001 |
| 同步导致上层业务权限超出 OMS 授权口径 | 以上层业务系统按 OMS 口径纠正为准，并记录差异 | 无 |
