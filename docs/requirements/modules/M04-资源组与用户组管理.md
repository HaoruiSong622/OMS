## 1. 模块概述

资源组与用户组管理是 OMS 授权体系的**主体管理层**，负责三件事：一是把被纳管的资源按业务范围归入不同的**资源组**；二是管理**用户组**自身的生命周期——创建、查询、删除，以及成员的添加与移除；三是维护用户组的两条授权关系：**绑定角色**（能力维度）与**关联资源组**（范围维度）。**账户不直接持有角色，也不直接关联资源组，其全部权限经用户组传递**，从而以用户组为粒度实现粗粒度管理。授权由两个**相互独立**的维度共同决定：**用户组绑定的角色**决定账户能否访问**某一类资源**，**用户组关联的资源组**决定账户能访问**该类资源中的哪些具体资源**。一个用户组可绑定多个角色、也可关联多个资源组，其成员的能力与资源范围分别取该用户组内各角色权限与各资源组范围的**并集**；**一个账户只能归属一个用户组**，不允许同时归属多个用户组。举例来说，某用户组绑定的角色只具备访问「模型推理」类资源的能力，则该组成员对任何「模型训练」类资源都无权访问，无论它归属哪个资源组；而对于「模型推理」类资源，若该用户组只关联资源组 A，则其成员只能访问资源组 A 内的模型推理资源，访问不了资源组 B 内的模型推理资源——这是资源范围的限制，而不是资源类型的限制。本模块上游依赖 M01 账户管理（账户是用户组的成员来源）与 M03 角色管理（内置角色是用户组的绑定对象），下游影响 M16 权限控制（权限判定须同时依据用户组绑定的角色能力与其关联的资源组范围）。OMS 本身不管理资源，资源由上层业务模块维护，本模块只维护资源分组与授权关系；资源与资源组之间的建模边界见主文档 OI-G-007。

| 项 | 内容 |

### 3.1 FR-RG-001 资源组创建、查询、删除

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-RG-001 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望创建资源组、按资源范围把纳管资源归入组内，并能查询和删除资源组，以便按业务范围划分权限域，让授权可以限定在指定资源范围内。

**③ 前置条件与触发方式**

- 前置条件：操作者具备资源组管理权限；待归组的资源已在 OMS 中纳管；已明确该资源组的划分范围与用途
- 触发方式：资源组管理页面的新建、查询与删除入口

**④ 主流程**

1. 操作者进入资源组管理页面，按名称、用途等条件查询现有资源组
2. 操作者选择新建资源组，填写资源组名称与用途说明
3. 系统校验资源组名称的唯一性与填写内容的完整性，创建资源组
4. 操作者将纳管资源归入该资源组，系统记录资源与资源组的归属关系
5. 操作者在资源组清单及其详情中查询该资源组下已归入的资源
6. 操作者发起删除时，系统校验该资源组下的资源归属与已建立的授权关系，处理完相关依赖后再删除该资源组

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 资源组名称与现有资源组重复 | 拒绝创建并提示重名 | 无 |
| 资源组名称或用途说明未填写 | 拒绝创建并提示补充必填信息 | 无 |
| 操作者无资源组管理权限 | 拒绝创建、修改与删除 | FR-PERM-001 |
| 资源组下仍归入有资源 | 拒绝删除，需先将组内资源移出或转移到其他资源组；资源必须先有归属才能纳入权限体系 | FR-RG-004 |
| 资源组已存在授权关系 | 删除前提示受影响的用户组与账户范围，确认后**其下已建立的授权关系随删除自动失效**，无需人工先行解除 | FR-RG-004 |
| 目标资源组不存在或已删除 | 提示资源组不可用，不执行操作 | 无 |
| 查询条件无匹配结果 | 返回空结果并提示调整查询条件 | 无 |
| 资源组删除完成后 | 资源组名称可被重新使用，原归属关系不再参与权限判定 | FR-PERM-001 |

**待确认**

### 3.2 FR-RG-002 用户组创建、查询、删除

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-RG-002 | V1.0 |

**② 需求描述**

作为系统管理员，我希望创建、查询和删除用户组，以便把需要相同资源访问范围的账户归为一组，按组复用资源访问授权，而不必逐人逐资源重复配置。

**③ 前置条件与触发方式**

- 前置条件：操作者具备用户组管理权限；用户组名称在 OMS 内唯一；待删除用户组的成员与已关联资源组的影响范围可评估
- 触发方式：资源组与用户组管理页面的用户组管理入口

**④ 主流程**

1. 操作者进入用户组管理入口，系统展示现有用户组清单及其成员数量
2. 操作者创建用户组，填写名称与用途说明
3. 系统校验名称唯一性与必填信息，保存该用户组
4. 操作者按名称、用途说明等条件查询用户组，并查看其成员、已绑定的角色与已关联的资源组
5. 操作者选择目标用户组发起删除，系统提示该用户组已关联的资源组与成员影响范围
6. 操作者确认后系统删除该用户组，并解除其与资源组的关联关系

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 用户组名称与现有用户组重复 | 拒绝创建并提示重名 | 无 |
| 名称或用途说明未填写 | 拒绝创建并提示补充必填信息 | 无 |
| 删除仍有成员的用户组 | 提示成员影响范围，确认后删除并解除成员的归属关系（不删除账户本身） | FR-ACC-007 |
| 删除已绑定角色或已关联资源组的用户组 | 提示受影响的角色绑定与资源组关联，确认后一并解除 | FR-RG-004 |
| 查询无匹配结果 | 展示空态，不视为异常 | 无 |
| 用户组的用途 | 承载角色绑定与资源组关联，是账户获得权限的唯一途径 | FR-ROLE-002 |
| 用户组创建或删除 | 须留痕，记录操作者、时间与影响范围 | FR-OPLOG-001 |
| 操作者无用户组管理权限 | 拒绝创建或删除 | FR-PERM-001 |

**待确认**

### 3.3 FR-RG-003 用户组成员管理（添加 / 移除用户）

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-RG-003 | V1.0 |

**② 需求描述**

作为系统管理员，我希望向用户组添加或移除账户，以便人员职责或岗位变化时，通过调整组成员快速调整其可访问的资源范围。

**③ 前置条件与触发方式**

- 前置条件：目标用户组已存在；待加入的账户已存在且处于可用状态（由 M01 账户管理维护）；操作者具备用户组管理权限
- 触发方式：用户组详情页的成员管理入口；账户详情页的用户组归属入口

**④ 主流程**

1. 操作者在用户组详情页进入成员管理
2. 系统展示该用户组当前成员以及可加入的账户清单
3. 操作者选择一个或多个账户加入该用户组，或选择已有成员移出；对已归属其他用户组的账户，可直接迁入本用户组，无需先移出
4. 系统校验账户的可用性与成员关系唯一性；账户已归属其他用户组时按迁入处理，自动解除其原用户组归属
5. 系统保存成员变更；迁入的账户其原用户组对应的权限立即失效，改按本用户组绑定的角色与关联的资源组获得能力与资源访问范围；该账户的已登录会话被强制过期，须重新登录
6. 操作者可在用户组详情与账户详情中查看最新的归属关系

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 待加入的账户不存在或已停用 | 拒绝加入并提示该账户当前不可用 | FR-ACC-004 |
| 重复加入同一账户 | 保持成员关系唯一，并提示该账户已在组内 | 无 |
| 成员被移出用户组 | 该账户随即失去通过该用户组获得的角色能力与资源访问范围 | FR-RG-004 |
| 账户已归属其他用户组 | 允许直接迁入本用户组，系统自动解除其原用户组归属，无需先移出 | FR-RG-004 |
| 账户迁入本用户组后 | 原用户组对应的角色能力与资源范围立即失效，改按本用户组的绑定与关联生效；该账户的已登录会话被强制过期，须重新登录 | FR-RG-004 |
| 账户未归属任何用户组 | 不具备任何角色能力，无法访问 OMS 功能与受管资源 | FR-ROLE-002 |
| 账户被删除 | 自动解除其用户组归属 | FR-ACC-007 |
| 成员添加或移除 | 须留痕，记录操作者、时间与变更内容 | FR-OPLOG-001 |
| 操作者无用户组管理权限 | 拒绝变更成员关系 | FR-PERM-001 |

**待确认**

无

### 3.4 FR-RG-004 用户组与资源组权限建模

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-RG-004 | V1.0 |

**② 需求描述**

作为系统管理员，我希望为用户组关联一个或多个资源组，以便界定该组成员可访问的具体资源范围（其能力由该用户组绑定的角色决定）、使资源授权可按用户组复用，而不必逐人逐资源重复授权。

**③ 前置条件与触发方式**

- 前置条件：用户组已存在且已包含成员（成员来源为 M01 账户管理）；资源组已存在且已归入资源；操作者具备授权配置权限
- 触发方式：资源组管理页面的授权配置入口

**④ 主流程**

1. 操作者在资源组清单中选择目标资源组，进入其授权配置
2. 系统展示可授权的用户组清单以及该资源组当前的授权情况
3. 操作者选择一个或多个用户组建立授权关系，界定该用户组可作用的资源范围
4. 系统校验授权关系的合法性
5. 系统保存授权关系，用户组成员据此获得对应资源组的资源范围；授权关系变更生效后，相关成员的已登录会话被强制过期，须重新登录
6. 操作者在资源组详情中查看、调整或解除已建立的授权关系

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 用户组或资源组不存在、已停用 | 拒绝建立授权关系并提示原因 | 无 |
| 关联关系承载的内容 | 只界定用户组可访问的**资源组范围**（即资源范围）；**与角色无关**，资源组关联不承载角色，角色能力也不因资源组而放宽 | FR-ROLE-002 |
| 用户组关联的粒度 | 只关联到资源组这一层，不对资源组内的资源或资源类型做单独关联；资源从属于资源组 | 无 |
| 资源组内某类资源的可访问性 | 用户组已关联该资源组，且其绑定的角色具备该类资源的能力时，成员即可访问该资源组内的这类资源 | FR-ROLE-002 |
| 用户组已关联某资源组，但其绑定的角色不具备该资源类型的能力 | 仍无法访问；资源类型层面的能力由用户组绑定的角色决定 | FR-PERM-001 |
| 重复建立同一授权关系 | 保持授权关系唯一，并提示该关系已存在 | 无 |
| 资源组的结构 | 资源组为**平铺结构**，不设父子层级，也不存在跨资源组的权限继承 | 无 |
| 用户组可访问范围的来源 | 仅来自其被关联的那些资源组，不因资源组之间的组织关系而扩大或缩小 | 无 |
| 账户的用户组归属 | 一个账户只能归属一个用户组；其能力与资源范围完全由该用户组决定，不与其他用户组叠加 | FR-RG-003 |
| 账户的用户组迁移 | 允许由系统管理员直接迁移到另一个用户组，一步完成；迁移后原用户组的角色能力与资源范围立即失效 | FR-RG-003 |
| 一个用户组关联多个资源组 | 允许，其成员可访问范围为所关联资源组的并集 | 无 |
| 用户组未绑定任何角色 | 该组成员不具备任何访问能力，即使已关联资源组 | FR-ROLE-002 |
| 用户组未关联任何资源组 | 该组成员虽具备角色能力，但没有任何可访问的具体资源 | FR-ROLE-002 |
| 用户组成员发生变动 | 成员新增或移除后，该账户的能力与资源范围随其所属用户组的授权范围重新计算；相关账户的已登录会话被强制过期，须重新登录 | FR-PERM-001 |
| 资源组被删除 | 其上已建立的授权关系随删除**自动失效**，无需人工先行解除；成员随即失去该资源组范围内的访问权限 | FR-RG-001 |
| 账户所属用户组未关联该资源组 | 不获得该资源组范围内任何资源的访问权限 | FR-PERM-001 |
| 操作者无授权配置权限 | 拒绝建立、调整或解除授权关系 | FR-PERM-001 |

**待确认**
