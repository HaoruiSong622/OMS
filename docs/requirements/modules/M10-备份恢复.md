## 1. 模块概述

备份恢复模块负责 OMS 自身数据的备份与恢复，是系统可运维性与数据安全的基础能力。它面向运维人员在变更、升级、故障与误操作等场景下提供可依赖的数据回退手段。备份方式为**全量备份，不提供增量备份**：手动备份由运维人员在页面上发起，周期性备份按配置的周期自动执行，二者都生成加密且带完整性校验的备份数据包；周期性备份的数据包按保留期自动清理，**手动备份的数据包不参与清理**。数据恢复**不提供页面入口**，仅通过**后台恢复脚本**执行——极端场景下数据损坏可能导致整个系统无法打开，页面入口不可依赖。模块通过任务中心承载备份任务的排队、进度与取消；备份数据包**一律保存至本地存储**，确保数据随时可回退；当 M14 第三方接入已配置并启用**唯一的 SFTP 连接**时，再**同步上传一份**至外部 SFTP 文件服务器作为外部副本，本模块不单独配置连接与凭据。本地存储不可用时备份即失败，外部上传不能替代本地保存。备份与恢复的结果同时向操作日志管理上报，形成可追溯的数据保护记录。本模块自身不承载业务功能，其能力直接影响全系统数据的安全与可恢复性。

| 项 | 内容 |
| --- | --- |
| 模块定位 | 为 OMS 自身数据提供全量备份与后台脚本恢复能力，保障数据可回退、可追溯、可演练 |
| 上游依赖 | M11 通用（任务中心承载备份与恢复任务的排队、进度与取消）；M14 第三方接入的 SFTP 文件服务器（已配置并启用其**全局唯一的 SFTP 连接**时，备份数据包在保存至本地后再同步上传一份至外部文件服务器） |
| 下游影响 | 全系统数据安全（数据可恢复性）；M08 操作日志管理（备份与恢复动作留痕） |
| 关键外部系统 | SFTP 文件服务器 |

### 3.1 FR-BAK-001 立即备份

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-BAK-001 | V1.0 |

**② 需求描述**

作为系统管理员，我希望手动发起一次全量备份（默认范围为全部子模块数据），以便在重大变更、升级或配置调整前留存一份可用于回退的数据副本。

**③ 前置条件与触发方式**

- 前置条件：操作者具备备份执行权限；备份对象范围**默认为全部子模块数据**，操作者可在发起时按需缩小；本地存储位置可用；M14 第三方接入已配置并启用**唯一的 SFTP 连接**时执行同步上传（未配置时仅保存本地）；系统当前无同类备份任务在执行
- 触发方式：备份恢复页面「立即备份」入口；事件（重大变更前由运维流程触发）

**④ 主流程**

1. 操作者进入备份恢复页面，确认备份对象范围（默认为全部子模块数据）
2. 系统展示本次备份的对象范围、预计数据量与对业务的影响提示
3. 操作者确认后，系统创建备份任务并交由任务中心统一排队执行
4. 系统按选定范围逐项备份数据，并将结果整理为备份文件
5. 系统对备份文件加密，并生成用于校验完整性的信息
6. 系统将备份文件保存至**本地存储**，并记录备份数据包信息（时间、类型、对象范围、结果）
7. 已配置并启用 SFTP 连接时，系统同步上传一份至外部文件服务器，并记录上传结果与同步状态
8. 备份完成后系统提示操作者，该备份数据包出现在已完成备份清单中

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 备份对象范围为默认值 | 覆盖全部子模块数据，操作者未作调整时按默认范围执行 | 无 |
| 备份对象范围为空或无法识别 | 拒绝发起备份并提示操作者重新选择范围 | 无 |
| 手动发起的备份数据包 | 不参与周期性备份的过期清理，须由操作者显式删除 | FR-BAK-002 |
| 备份文件须加密并带完整性校验信息 | 备份文件在保存前完成加密与校验信息生成；校验不通过的备份数据包标记为不可用，不得用于恢复 | FR-BAK-004 |
| 本地存储位置不可访问或空间不足 | 任务失败并保留失败原因，提示操作者处理本地存储后重试；外部上传不能替代本地保存 | FR-BAK-003 |
| 已配置并启用 SFTP 连接时 | 本地保存完成后同步上传一份至外部文件服务器；上传失败不影响本地备份成功的判定，按策略重试并产生告警，在清单中标注该备份未同步；后续上传成功时主动向 M17 告警管理上报消除信息 | FR-3RD-002、FR-ALM-005 |
| 未配置 SFTP 连接时 | 仅在本地存储保存，不进行外部上传，备份照常成功 | FR-3RD-002 |
| 备份期间对业务的影响须可控 | 备份执行不得阻断正常业务操作，页面对可能的影响作出提示 | 无 |
| 已存在同类备份任务在执行 | 提示存在进行中的任务，并按任务中心规则排队或拒绝发起 | FR-COM-002 |
| 操作者无备份执行权限 | 拒绝发起备份并提示 | FR-PERM-001 |
| 备份动作须留痕 | 记录操作者、时间、备份类型、对象范围与结果 | FR-COM-003 |

OI-M10-003：已配置 SFTP 连接时，同步上传失败是否影响本次备份的最终状态判定（本地保存成功即视为成功，还是标记为部分成功），以及是否需要提供手动补传入口？（责任方：业务运维/产品，期望闭环：<日期>）

### 3.2 FR-BAK-002 周期性备份

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-BAK-002 | V1.0 |

**② 需求描述**

作为系统管理员，我希望按配置的周期与时间点自动执行**全量备份**，以便无需人工干预即可持续生成可用于回退的备份数据包。

**③ 前置条件与触发方式**

- 前置条件：周期备份策略已配置（周期、时间点、保留期）；策略中已明确备份对象范围；本地存储位置可用；M14 第三方接入已配置并启用**唯一的 SFTP 连接**时执行同步上传（未配置时仅保存本地）；系统时间与业务低峰时段设置正确
- 触发方式：定时任务

**④ 主流程**

1. 系统按已配置的周期与时间点触发周期性备份
2. 系统按策略确认本次备份的对象范围（默认为全部子模块数据）
3. 任务中心排队执行备份，系统按范围生成备份文件
4. 系统对备份文件加密，并生成用于校验完整性的信息
5. 系统将备份文件保存至**本地存储**，并记录备份数据包信息
6. 已配置并启用 SFTP 连接时，系统同步上传一份至外部文件服务器，并记录上传结果与同步状态
7. 系统记录本次执行结果；失败时按策略触发告警与重试
8. 系统按保留期清理已过期的**周期性**备份数据包；手动备份的数据包不参与清理

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 备份周期、时间点与保留期均可配置 | 配置变更自下一个周期生效，已产生的备份数据包不受影响 | 无 |
| 备份方式 | 固定为**全量备份**，不提供增量备份 | 无 |
| 备份执行失败 | 触发告警通知责任人，并按策略自动重试；重试仍失败时保留失败原因供查询 | FR-BAK-003 |
| 后续备份成功（异常恢复） | 主动向 M17 告警管理上报消除信息，使备份失败告警消除 | FR-ALM-005 |
| 周期性备份数据包达到保留期 | 按保留期自动清理；**手动发起的备份数据包不参与清理** | FR-BAK-001 |
| 本地存储位置不可用 | 任务失败并告警，待本地存储恢复后按策略重试；外部上传不能替代本地保存 | FR-BAK-001 |
| 已配置并启用 SFTP 连接时 | 本地保存完成后同步上传一份至外部文件服务器，上传结果与同步状态单独记录，失败处理同手动备份 | FR-BAK-001 |
| 备份文件加密与完整性校验 | 加密与校验须按周期任务同样要求执行；校验不通过的备份数据包不得用于恢复 | FR-BAK-004 |
| 系统时间或时区被调整 | 周期触发时机以调整后的系统时间为准，并提示操作者可能造成的触发偏差 | 无 |

**待确认**

OI-M10-004：周期性备份数据包按保留期清理时，外部 SFTP 上的同步副本是否随之清理，由 OMS 自动清理还是由外部文件服务器侧自行管理？（责任方：业务运维/产品，期望闭环：<日期>）

### 3.3 FR-BAK-003 备份进度查询

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-BAK-003 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望查看备份任务的进度、状态与失败原因，以及已完成备份清单，以便及时掌握数据保护情况并在出现失败时快速定位处理。

**③ 前置条件与触发方式**

- 前置条件：操作者具备备份查询权限；系统中存在进行中或历史的备份任务
- 触发方式：备份恢复页面的备份任务列表入口；事件（收到备份失败告警后查看）

**④ 主流程**

1. 操作者进入备份任务列表
2. 系统展示进行中与历史备份任务的状态与进度
3. 操作者选择任一任务查看详情，包括备份类型、对象范围、本地存放位置、SFTP 同步状态、开始与结束时间
4. 任务失败时，系统展示失败原因及已重试情况
5. 操作者查看已完成备份清单，包括备份数据包时间、类型、对象范围、本地存放位置、SFTP 同步状态与可用性

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 备份任务的状态展示 | 覆盖排队中、执行中、成功、失败、已取消 | FR-COM-002 |
| 任务正在执行 | 进度持续刷新，无需操作者手动刷新页面 | 无 |
| 备份任务失败 | 展示失败原因与已重试次数，并可跳转查看相关告警信息 | FR-BAK-002 |
| 已完成备份清单 | 展示备份数据包时间、类型、对象范围、本地存放位置、SFTP 同步状态与可用性；未通过完整性校验的备份数据包标记为不可用 | FR-BAK-001 |
| 配置了 SFTP 连接但某次备份上传失败 | 该备份仍按本地副本判定为成功可用，同时标注同步失败并保留失败原因，提示运维补传 | FR-BAK-001 |
| 查询操作 | 查询不得影响正在执行的备份任务，也不得修改任何备份文件 | 无 |
| 操作者无备份查询权限 | 拒绝访问并提示 | FR-PERM-001 |

### 3.4 FR-BAK-004 数据恢复

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-BAK-004 | V1.0 |

**② 需求描述**

作为系统管理员，我希望通过后台恢复脚本从指定备份数据包恢复 OMS 数据，以便在数据损坏、误操作或系统故障（包括系统已无法打开）时找回数据并恢复业务。

**③ 前置条件与触发方式**

- 前置条件：已存在完整性校验通过的可用备份数据包（以**本地存储**的备份数据包为准，外部 SFTP 副本仅作留存）；恢复脚本已随版本交付且可在目标环境执行；执行者具备服务器操作权限并已获得恢复授权；已确认恢复范围与停机窗口；已完成对当前数据的保护性备份
- 触发方式：**后台恢复脚本**——由具备权限的运维人员在服务器上执行（不提供页面入口）；事件（故障、误操作或系统无法打开时的应急流程触发）

**④ 主流程**

1. 运维人员确认故障场景，并选定拟用于恢复的备份数据包
2. 运维人员在后台执行恢复脚本，并指定该备份数据包
3. 脚本校验数据包的完整性与可用性；校验不通过时终止并输出原因
4. 脚本要求执行者二次确认，明确恢复将覆盖现有数据且不可逆
5. 脚本确认系统处于停止对外服务的状态后执行数据恢复
6. 恢复完成后，脚本校验恢复数据的完整性并核对恢复范围
7. 脚本输出恢复结果与过程记录，供留痕与审计追溯

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 恢复入口 | **仅通过后台恢复脚本执行，不提供页面恢复入口**；极端场景下系统可能已无法打开，页面入口不可依赖 | 无 |
| 未指定数据包或所选数据包不可用 | 脚本终止并输出原因 | FR-BAK-001 |
| 恢复前须二次确认 | 必须由执行者显式确认，并提示恢复将覆盖现有数据且不可逆 | 无 |
| 恢复期间系统不可用 | 脚本须确认系统已停止对外服务后再执行，避免恢复过程中产生新的数据写入 | 无 |
| 恢复完成后须校验数据完整性 | 校验不通过时判定恢复失败，保留现场，不得直接恢复对外服务 | 无 |
| 恢复动作必须留痕 | 记录执行者、时间、所用备份数据包、恢复范围与结果，且记录不可被修改 | FR-COM-003 |
| 恢复失败或中断 | 保留失败原因，由执行者决定重试或回退到恢复前完成的保护性备份 | FR-BAK-003 |
| 恢复演练 | 支持在非生产环境或指定范围内开展恢复演练，演练不影响生产数据，并记录演练结果 | 无 |
