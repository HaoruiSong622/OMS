## 1. 模块概述

证书管理模块统一管理两类证书：OMS 对外提供 HTTPS 服务所使用的 Nginx 证书，以及 OMS 各服务之间通信所需的证书。业务运维人员可查看当前 Nginx 证书的颁发者、有效期、适用域名与到期状态；**系统管理员**可在证书到期或变更时上传证书与私钥完成替换，也可通过 M14 接入的 CA 服务器对 Nginx 证书进行续约——**即便原证书最初为自签名生成，同样可以续约为 CA 签发的证书**。服务间通信证书**不依赖外部 CA**：在**安装部署阶段以自签名方式生成**，并颁发给各个微服务，供服务之间进行双向认证。证书的到期与异常状态是巡检模块的输入，服务间证书的可用性直接决定全系统加密通信能否建立。

| 项 | 内容 |
| --- | --- |
| 模块定位 | 统一管理对外 HTTPS 服务的 Nginx 证书与服务间通信证书，支撑全系统加密通信 |
| 上游依赖 | M14 第三方接入提供 CA 服务器接入能力，用于**Nginx 对外证书**的签发与续约；服务间通信证书由安装部署过程自签名生成，不经 CA |
| 下游影响 | 全系统加密通信依赖服务间证书；M12 证书巡检以本模块的证书为巡检对象 |
| 关键外部系统 | CA 服务器（用于 Nginx 对外证书的签发与续约） |

### 3.1 FR-CERT-001 查看 Nginx 证书

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-CERT-001 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望在证书管理页面查看当前 Nginx 证书的颁发者、有效期、适用域名与到期状态，以便判断证书是否仍然有效、是否需要安排更换。

**③ 前置条件与触发方式**

- 前置条件：操作者具备证书查看权限；OMS 对外 HTTPS 服务已配置 Nginx 证书
- 触发方式：证书管理页面证书详情入口

**④ 主流程**

1. 操作者进入证书管理页面
2. 系统展示当前 Nginx 证书的颁发者、有效期与适用域名等信息
3. 系统根据有效期给出到期状态提示，区分正常、即将过期与已过期
4. 系统展示证书的最近一次变更情况，供操作者核对
5. 操作者按需查看后离开页面，本操作不改变证书状态

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 尚未配置 Nginx 证书 | 明确提示当前无证书，并指引进行导入 | FR-CERT-002 |
| 证书信息无法获取 | 提示获取失败，不展示过时或推断的信息 | 无 |
| 证书已过期 | 以显著方式标记为已过期 | FR-INSP-001 |
| 证书临近到期 | 提示可通过上传或 CA 续约完成更换 | FR-CERT-002 |
| 适用域名与实际对外访问入口不一致 | 提示不一致风险，供操作者确认 | 无 |
| 操作者无查看权限 | 拒绝查看并提示无权限 | 无 |

**待确认**

无

### 3.2 FR-CERT-002 更新/导入 Nginx 证书

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-CERT-002 | V1.0 |

**② 需求描述**

作为系统管理员，我希望上传新的证书与私钥、或通过已接入的 CA 服务器续约，来完成 Nginx 证书替换，以便在证书到期前完成更换、避免对外 HTTPS 服务中断。

**③ 前置条件与触发方式**

- 前置条件：操作者具备 Nginx 证书更新权限；采用上传方式时已获取与适用域名匹配的新证书及对应私钥；采用续约方式时 M14 的 CA 服务器接入已配置且可用；系统具备留存原证书备份的条件
- 触发方式：证书管理页面更新/续约入口；事件（证书临近到期时发起续约）

**④ 主流程**

1. 操作者进入证书更新入口，选择更新方式：上传新证书与私钥，或通过已接入的 CA 服务器续约
2. 上传方式时选择待上传的证书与私钥；续约方式时确认适用域名
3. 系统校验来源有效性：上传内容需格式合规且私钥与证书匹配；续约请求需被已接入的 CA 接受
4. 校验通过后，系统自动备份当前正在使用的原证书
5. 系统以新证书替换原证书，使对外 HTTPS 服务平滑生效
6. 系统记录本次更新的方式（上传或 CA 续约）、操作者、时间与结果，供后续追溯
7. 更新完成后，操作者在证书详情中确认新证书的颁发者、有效期与到期状态

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 更新方式 | 支持上传与 CA 续约两种方式，二者都须完成替换并对使用方生效，避免新旧证书并存 | 无 |
| 上传内容格式不合规 | 拒绝替换并提示不满足格式要求 | 无 |
| 采用 CA 续约但 CA 不可用或无响应 | 拒绝替换并给出明确失败原因，保持原证书继续可用；证书临近到期时按 FR-3RD-003 产生告警并标记为待处理，**不回退为自签证书** | FR-3RD-003 |
| 原证书为自签名生成 | 允许通过 CA 续约将其替换为 CA 签发的证书 | FR-3RD-003 |
| 私钥与证书不匹配 | 拒绝替换并提示不匹配 | 无 |
| 证书与适用域名不匹配（含续约所得证书） | 提示不匹配风险，需操作者确认后方可继续 | FR-CERT-001 |
| 替换前 | 系统自动备份原证书，备份可用于回滚 | 无 |
| 替换生效过程 | 对外 HTTPS 服务平滑切换，不中断既有访问 | 无 |
| 替换执行失败 | 自动回滚到原证书，保持服务可用，并提示失败 | 无 |
| 替换完成 | 留存本次操作记录，包含操作者、时间与结果 | 无 |
| 证书替换或续约成功（异常恢复） | 主动向 M17 告警管理上报清除信息，使证书到期、续期失败相关告警清除 | FR-ALM-005 |
| 操作者无更新权限 | 拒绝替换并提示无权限 | 无 |

**待确认**

无

### 3.3 FR-CERT-003 服务间通信证书生成

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-CERT-003 | V1.0 |

**② 需求描述**

作为系统管理员，我希望在安装部署阶段以**自签名**方式生成服务间通信证书并颁发给各个微服务，以便服务之间的调用是可信的、未被冒名接入的，且不依赖外部 CA 服务器。

**③ 前置条件与触发方式**

- 前置条件：系统处于**安装部署阶段**；各微服务的服务标识与信任范围已确定；部署流程已包含服务间证书生成步骤
- 触发方式：**安装部署（初始化）过程**触发，不提供页面生成入口

**④ 主流程**

1. 安装部署流程在初始化阶段确定各微服务的服务标识与信任范围
2. 部署流程以**自签名**方式生成服务间通信证书，不向任何外部 CA 申请
3. 部署流程将证书与对应私钥颁发到各个微服务
4. 各微服务在服务间调用时使用该证书进行双向认证
5. 部署流程记录本次生成的证书清单及其有效期，供后续查看与巡检
6. 证书临近到期或需要更换时，通过重新执行部署流程或指定的运维手段重新生成并颁发

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 服务间通信证书的生成方式 | **自签名**生成，**不依赖外部 CA 服务器** | 无 |
| 生成时机与入口 | 在安装部署（初始化）阶段由部署流程完成，**不提供页面生成入口** | 无 |
| 证书的颁发对象 | 各个微服务，用于服务之间的双向认证 | 无 |
| 部署流程未完成证书生成 | 视为部署未完成，不得启动服务间通信 | 无 |
| 证书的有效期与到期状态 | 每一张服务间证书均可查询，并纳入证书巡检范围 | FR-INSP-001 |
| 证书续期或更换 | 通过重新执行部署流程或指定的运维手段重新生成并颁发，避免新旧证书混用 | 无 |
| 服务间证书被替换 | 明确标识当前有效证书，避免旧证书继续被信任 | 无 |
| 生成失败 | 部署流程终止并输出原因，不得使用不完整证书启动服务 | 无 |

**待确认**

无

### 3.4 FR-CERT-004 生成 CSR 文件

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-CERT-004 | V1.0 |

**② 需求描述**

作为系统管理员，我希望按选定的私钥算法与长度生成 CSR 文件（并可自定义证书主题信息），以便把 CSR 交由 CA 签发后，用签发结果完成 Nginx 证书的更新与续约。

**③ 前置条件与触发方式**

- 前置条件：操作者具备证书管理权限；OMS 对外 HTTPS 服务已配置 Nginx 证书；系统具备生成私钥与 CSR 的能力；如需自定义主题信息，已明确国家、省份、城市、公司、部门与常用名
- 触发方式：证书管理页面的「生成CSR文件」入口

**④ 主流程**

1. 操作者进入证书管理页面，选择「生成CSR文件」
2. 系统展示私钥算法与私钥长度选项：**私钥算法只提供 RSA**；**私钥长度可选 2048 / 3072 / 4096**，默认 2048
3. 操作者按需打开「高级」开关：关闭时主题信息整体隐藏；打开后展示并支持修改主题信息，
   各项默认值为 **国家（C）= CN、省份（S）= SiChuan、城市（L）= 空、公司（O）= Huawei、部门（OU）= 空、
   常用名（CN）= 当前软件登录网址或 IP**
4. 操作者确认后，系统按所选算法与长度生成私钥，并据主题信息生成 CSR 文件
5. 系统交付 CSR 文件，供操作者提交给 CA 签发
6. CA 签发完成后，操作者通过「更新/导入 Nginx 证书」导入签发结果（见 FR-CERT-002）

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 私钥算法 | **只提供 RSA**，不提供其它算法选项 | 无 |
| 私钥长度 | 可选 **2048 / 3072 / 4096**，默认 2048 | 无 |
| 高级开关关闭 | 主题信息**整体隐藏**，按默认值生成 CSR，不要求操作者填写 | 无 |
| 高级开关打开 | 展示国家（C）、省份（S）、城市（L）、公司（O）、部门（OU）、常用名（CN）并可修改 | 无 |
| 主题信息默认值 | C=CN、S=SiChuan、L=空、O=Huawei、OU=空、CN=当前软件登录网址或 IP（取访问 OMS 的网址或 IP；无法获取时回落为回环地址） | 无 |
| 常用名（CN） | 高级开关打开时为必填，不允许为空 | 无 |
| 城市（L）与部门（OU） | 允许留空，留空时不在 CSR 中写入该字段 | 无 |
| CSR 文件的使用 | 生成的 CSR 须交由 CA 签发后再导入，OMS 不保存未签发的证书 | 无 |
| 操作者无证书管理权限 | 拒绝生成并提示 | FR-PERM-001 |

**待确认**

无

### 3.5 FR-CERT-005 配置证书过期预警

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-CERT-005 | V1.0 |

**② 需求描述**

作为系统管理员，我希望为当前证书开启或关闭过期预警并设置预警天数，以便在证书到期前获得足够的时间安排更换，同时避免不需要预警时持续产生提示。

**③ 前置条件与触发方式**

- 前置条件：操作者具备证书管理权限；OMS 对外 HTTPS 服务已配置 Nginx 证书；证书的到期时间可读取
- 触发方式：证书管理页面的「修改」入口

**④ 主流程**

1. 操作者在证书管理页面选择「修改」
2. 系统展示当前的过期预警开关状态与预警天数
3. 操作者打开或关闭过期预警；关闭时预警天数置灰且不可编辑
4. 操作者设置过期预警天数，取值范围 **30-90 天**
5. 系统校验取值合法性并保存
6. 证书列表与证书详情同步展示最新的预警状态与预警天数

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 过期预警天数超出取值范围 | 拒绝保存并提示取值范围为 **30-90 天** | 无 |
| 过期预警关闭 | 不再产生证书到期预警；预警天数置灰且不参与校验，原取值保留 | 无 |
| 过期预警开启 | 在证书到期前按设定的天数给出到期预警；预警到达后按 M17 告警管理产生告警 | FR-ALM-001 |
| 修改结果 | 保存后在证书列表的「过期预警」「过期预警天数」两列立即生效 | 无 |
| 操作者无证书管理权限 | 拒绝修改并提示 | FR-PERM-001 |

**待确认**

无
