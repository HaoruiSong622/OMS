## 1. 模块概述

证书管理模块统一管理两类证书：OMS 对外提供 HTTPS 服务所使用的 Nginx 证书，以及 OMS 各服务之间通信所需的证书。业务运维人员可查看当前 Nginx 证书的颁发者、有效期、适用域名与到期状态；安全管理员可在证书到期或变更时上传证书与私钥完成替换，也可通过 M14 接入的 CA 服务器对 Nginx 证书进行续约——**即便原证书最初为自签名生成，同样可以续约为 CA 签发的证书**。服务间通信证书**不依赖外部 CA**：在**安装部署阶段以自签名方式生成**，并颁发给各个微服务，供服务之间进行双向认证。证书的到期与异常状态是巡检模块的输入，服务间证书的可用性直接决定全系统加密通信能否建立。

| 项 | 内容 |
| --- | --- |
| 模块定位 | 统一管理对外 HTTPS 服务的 Nginx 证书与服务间通信证书，支撑全系统加密通信 |
| 上游依赖 | M14 第三方接入提供 CA 服务器接入能力，用于**Nginx 对外证书**的签发与续约；服务间通信证书由安装部署过程自签名生成，不经 CA |
| 下游影响 | 全系统加密通信依赖服务间证书；M12 证书巡检以本模块的证书为巡检对象 |
| 关键外部系统 | CA 服务器（用于 Nginx 对外证书的签发与续约） |

### 3.1 FR-CERT-001 查看 Nginx 证书

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-CERT-001 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望在证书管理页面查看当前 Nginx 证书的颁发者、有效期、适用域名与到期状态，以便判断证书是否仍然有效、是否需要安排更换。

**③ 前置条件与触发方式**

- 前置条件：操作者具备证书查看权限；OMS 对外 HTTPS 服务已配置 Nginx 证书
- 触发方式：证书管理页面证书详情入口

**④ 主流程**

1. 操作者进入证书管理页面
2. 系统展示当前 Nginx 证书的颁发者、有效期与适用域名等信息
3. 系统根据有效期给出到期状态提示，区分正常、即将过期与已过期
4. 系统展示证书的最近一次变更情况，供操作者核对
5. 操作者按需查看后离开页面，本操作不改变证书状态

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 尚未配置 Nginx 证书 | 明确提示当前无证书，并指引进行导入 | FR-CERT-002 |
| 证书信息无法获取 | 提示获取失败，不展示过时或推断的信息 | 无 |
| 证书已过期 | 以显著方式标记为已过期 | FR-INSP-001 |
| 证书临近到期 | 提示可通过上传或 CA 续约完成更换 | FR-CERT-002 |
| 适用域名与实际对外访问入口不一致 | 提示不一致风险，供操作者确认 | 无 |
| 操作者无查看权限 | 拒绝查看并提示无权限 | 无 |

### 3.2 FR-CERT-002 更新/导入 Nginx 证书

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-CERT-002 | V1.0 |

**② 需求描述**

作为安全管理员，我希望上传新的证书与私钥、或通过已接入的 CA 服务器续约，来完成 Nginx 证书替换，以便在证书到期前完成更换、避免对外 HTTPS 服务中断。

**③ 前置条件与触发方式**

- 前置条件：操作者具备 Nginx 证书更新权限；采用上传方式时已获取与适用域名匹配的新证书及对应私钥；采用续约方式时 M14 的 CA 服务器接入已配置且可用；系统具备留存原证书备份的条件
- 触发方式：证书管理页面更新/续约入口；事件（证书临近到期时发起续约）

**④ 主流程**

1. 操作者进入证书更新入口，选择更新方式：上传新证书与私钥，或通过已接入的 CA 服务器续约
2. 上传方式时选择待上传的证书与私钥；续约方式时确认适用域名
3. 系统校验来源有效性：上传内容需格式合规且私钥与证书匹配；续约请求需被已接入的 CA 接受
4. 校验通过后，系统自动备份当前正在使用的原证书
5. 系统以新证书替换原证书，使对外 HTTPS 服务平滑生效
6. 系统记录本次更新的方式（上传或 CA 续约）、操作者、时间与结果，供后续追溯
7. 更新完成后，操作者在证书详情中确认新证书的颁发者、有效期与到期状态

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 更新方式 | 支持上传与 CA 续约两种方式，二者都须完成替换并对使用方生效，避免新旧证书并存 | 无 |
| 上传内容格式不合规 | 拒绝替换并提示不满足格式要求 | 无 |
| 采用 CA 续约但 CA 不可用或无响应 | 拒绝替换并给出明确失败原因，保持原证书继续可用；证书临近到期时按 FR-3RD-003 产生告警并标记为待处理，**不回退为自签证书** | FR-3RD-003 |
| 原证书为自签名生成 | 允许通过 CA 续约将其替换为 CA 签发的证书 | FR-3RD-003 |
| 私钥与证书不匹配 | 拒绝替换并提示不匹配 | 无 |
| 证书与适用域名不匹配（含续约所得证书） | 提示不匹配风险，需操作者确认后方可继续 | FR-CERT-001 |
| 替换前 | 系统自动备份原证书，备份可用于回滚 | 无 |
| 替换生效过程 | 对外 HTTPS 服务平滑切换，不中断既有访问 | 无 |
| 替换执行失败 | 自动回滚到原证书，保持服务可用，并提示失败 | 无 |
| 替换完成 | 留存本次操作记录，包含操作者、时间与结果 | 无 |
| 证书替换或续约成功（异常恢复） | 主动向 M17 告警管理上报消除信息，使证书到期、续期失败相关告警消除 | FR-ALM-005 |
| 操作者无更新权限 | 拒绝替换并提示无权限 | 无 |

**待确认**

无

### 3.3 FR-CERT-003 服务间通信证书生成

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-CERT-003 | V1.0 |

**② 需求描述**

作为系统管理员，我希望在安装部署阶段以**自签名**方式生成服务间通信证书并颁发给各个微服务，以便服务之间的调用是可信的、未被冒名接入的，且不依赖外部 CA 服务器。

**③ 前置条件与触发方式**

- 前置条件：系统处于**安装部署阶段**；各微服务的服务标识与信任范围已确定；部署流程已包含服务间证书生成步骤
- 触发方式：**安装部署（初始化）过程**触发，不提供页面生成入口

**④ 主流程**

1. 安装部署流程在初始化阶段确定各微服务的服务标识与信任范围
2. 部署流程以**自签名**方式生成服务间通信证书，不向任何外部 CA 申请
3. 部署流程将证书与对应私钥颁发到各个微服务
4. 各微服务在服务间调用时使用该证书进行双向认证
5. 部署流程记录本次生成的证书清单及其有效期，供后续查看与巡检
6. 证书临近到期或需要更换时，通过重新执行部署流程或指定的运维手段重新生成并颁发

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 服务间通信证书的生成方式 | **自签名**生成，**不依赖外部 CA 服务器** | 无 |
| 生成时机与入口 | 在安装部署（初始化）阶段由部署流程完成，**不提供页面生成入口** | 无 |
| 证书的颁发对象 | 各个微服务，用于服务之间的双向认证 | 无 |
| 部署流程未完成证书生成 | 视为部署未完成，不得启动服务间通信 | 无 |
| 证书的有效期与到期状态 | 每一张服务间证书均可查询，并纳入证书巡检范围 | FR-INSP-001 |
| 证书续期或更换 | 通过重新执行部署流程或指定的运维手段重新生成并颁发，避免新旧证书混用 | 无 |
| 服务间证书被替换 | 明确标识当前有效证书，避免旧证书继续被信任 | 无 |
| 生成失败 | 部署流程终止并输出原因，不得使用不完整证书启动服务 | 无 |

**待确认**

无
