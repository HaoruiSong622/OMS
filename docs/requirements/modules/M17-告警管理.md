## 1. 模块概述

告警管理模块统一接收来自 OMS 各子模块的各类告警，提供集中展示、告警消除、屏蔽与对外上报能力。它解决告警来源分散、重复告警多、告警是否消除不透明的问题，帮助运维人员在统一入口掌握异常并跟踪其消除。上游依赖 M14 第三方接入提供的 SNMP 告警上报通道，以及 M12 巡检发现的异常结果；下游影响运维人员的告警查看与消除效率、上层网管系统的告警视图。关键外部系统为接收 OMS 告警上报的上层网管系统。

| 项 | 内容 |
| --- | --- |
| 模块定位 | OMS 告警的统一入口与统一出口，实现告警的接收、展示、消除、屏蔽与上报 |
| 上游依赖 | M14 第三方接入提供 SNMP 告警上报通道；M12 巡检在发现异常时产生告警 |
| 下游影响 | 运维人员的告警查看与消除效率；上层网管系统的告警视图与告警口径 |
| 关键外部系统 | 上层网管系统（通过 M14 的 SNMP 通道接收 OMS 告警上报） |

### 3.1 FR-ALM-001 接收告警

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-ALM-001 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望 OMS 统一接收来自各子模块的各类告警，以便在一个入口掌握全部异常。

**③ 前置条件与触发方式**

- 前置条件：告警来源已接入并处于启用状态；告警分级规则已配置；OMS 与告警来源的时间口径一致；接收能力运行正常
- 触发方式：事件——子模块产生异常事件时触发

**④ 主流程**

1. 告警来源产生告警并送达 OMS
2. 系统接收告警并校验必要信息是否齐全
3. 系统按已配置规则判定告警级别
4. 系统按来源与告警内容，判断新告警是否为**尚未消除**的既有告警的重复（**不设时间窗口**），并执行去重与合并
5. 系统生成新告警，或更新既有告警的最近发生时间与发生次数，进入活动告警
6. 系统按告警级别与订阅关系通知相关人员（可选）

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 同一来源、相同内容的告警且既有告警**尚未消除**时重复上报 | 判定为重复告警：**不重复展示**，更新最近发生时间并累计发生次数；**不受时间窗口限制**，只要既有告警未消除即并认定为重复 | 无 |
| 既有告警已消除后又收到相同内容的告警 | 视为**新告警**重新生成，从零开始累计发生次数，不并入已消除的历史告警 | FR-ALM-005 |
| 告警必要信息缺失 | 不得静默丢弃，须保留接收记录并提示来源方补充信息 | 无 |
| 告警级别规则未覆盖该告警 | 按默认级别接收，并提示管理员补齐分级规则 | 无 |
| 告警来源未接入或已停用 | 拒绝接收并记录来源信息，供管理员排查 | 无 |
| 短时间内告警量突增（告警风暴） | 按来源执行限流与合并，关键级别告警不得被丢弃 | 无 |
| 来源时间与 OMS 时间偏差过大 | 以 OMS 接收时间为准，并在告警记录中标注偏差 | 无 |
| 重复告警的后续处理 | 即使不在页面重复展示，仍须按上报范围**重复上报 SNMP** | FR-ALM-004 |

### 3.2 FR-ALM-002 告警展示

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-ALM-002 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望按级别、时间、来源与状态查询告警，并在活动告警与历史告警之间切换，以便快速定位尚未消除的异常，并追溯已消除的告警。

**③ 前置条件与触发方式**

- 前置条件：告警已被接收并生成记录；用户具备告警查看权限；查询条件在系统允许的范围内
- 触发方式：页面入口——告警列表页与告警详情页；系统按配置实时刷新告警

**④ 主流程**

1. 用户进入告警页面
2. 系统按用户权限展示其可见的**活动告警**（未消除的告警）
3. 用户按级别、时间、来源等维度进行筛选与排序
4. 用户打开告警详情查看完整信息
5. 用户切换到**历史告警**视图，查询已消除的告警
6. 页面实时刷新新增告警、重复告警的次数与时间更新，以及告警消除等变化

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 用户无告警查看权限 | 菜单与列表均不可见，相应的后台能力调用同样被拒绝 | FR-PERM-001、FR-PERM-002 |
| 告警已被屏蔽 | 不出现在常规告警列表与统计中，仅可在追溯入口查看 | FR-ALM-003 |
| 活动告警与历史告警的区分 | 以**是否消除**为准：未消除的进入活动告警列表，已消除的进入历史告警视图 | FR-ALM-005 |
| 重复告警到达 | 列表不新增条目，刷新该告警的最近发生时间与发生次数 | FR-ALM-001 |
| 新告警到达 | 列表实时刷新，并按级别突出显示 | 无 |
| 查询时间范围或结果量过大 | 提示收窄查询条件，避免影响页面使用 | 无 |
| 授权角色追溯被屏蔽的告警 | 可在追溯入口查询屏蔽记录及命中规则 | FR-ALM-003 |
| 已消除的告警 | 不在活动告警列表中展示，转入历史告警视图，仅作查询与追溯 | FR-ALM-005 |

**待确认**

### 3.3 FR-ALM-003 告警屏蔽

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-ALM-003 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望对已知且无需处理的告警配置屏蔽规则与生效时间段，以便减少无效告警对查看与消除工作的干扰。

**③ 前置条件与触发方式**

- 前置条件：操作者具备屏蔽规则维护权限；屏蔽范围（来源、类型或关键字）已明确；生效时间段已确定；屏蔽原因已填写
- 触发方式：页面入口——屏蔽规则维护页面；定时任务——生效与失效时间到达时自动启用或停用规则

**④ 主流程**

1. 操作者新建或修改屏蔽规则，选择按来源、类型或关键字匹配
2. 操作者设置生效时间段并填写屏蔽原因
3. 系统校验屏蔽范围与生效时间段的合法性
4. 系统保存规则并记录本次维护动作
5. 到达生效时间后规则自动生效，命中的告警按规则处理
6. 到达失效时间后规则自动失效，相关告警恢复正常展示与上报

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 告警命中屏蔽规则 | 不再展示与上报，但告警数据完整保留，可通过追溯入口查询 | FR-ALM-004 |
| 屏蔽记录被删除 | 不允许删除屏蔽记录，只能停用规则或让规则自然失效 | 无 |
| 屏蔽规则的维护动作 | 全程留痕，可供审计管理员审计 | 无 |
| 多条规则同时命中同一告警 | 按最先生效的规则处理，并在追溯记录中标注命中的规则 | 无 |
| 未设置生效时间段 | 规则持续生效，直至被停用 | 无 |
| 非授权角色维护屏蔽规则 | 拒绝操作 | FR-PERM-003 |
| 屏蔽范围过大（如仅按通用关键字匹配） | 保存前提示可能被屏蔽的范围，要求操作者确认 | 无 |
| 屏蔽生效期间发生的告警 | 标注为已屏蔽（**独立于消除状态的标记**），屏蔽失效后仍可追溯 | FR-ALM-002 |

**待确认**

### 3.4 FR-ALM-004 告警 SNMP 上报

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-ALM-004 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望 OMS 把符合条件的告警上报给上层网管系统，上报内容覆盖告警的**产生、重复发生与消除**，以便上层网管与 OMS 保持一致的告警视图并能同步关闭已消除的告警。

**③ 前置条件与触发方式**

- 前置条件：上报开关已开启；上报范围与级别策略已确定；待上报告警已完成级别判定；M14 第三方接入的 SNMP 上报通道已配置并启用
- 触发方式：事件——告警产生、重复发生或消除且满足上报条件时触发；定时任务——对上报失败的内容执行重试

**④ 主流程**

1. 管理员开启上报并配置上报范围（按级别、来源或类型）
2. 满足上报条件的告警**产生、重复发生或消除**时，系统准备对应的上报内容
3. 系统通过 M14 已启用的 SNMP 上报通道将上报内容发送给上层网管系统
4. 系统记录上报结果
5. 上报失败时由 M14 的上报通道按策略重试；持续失败则产生告警并保留待上报内容
6. 管理员查询上报结果与历史上报情况

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 上报范围 | 覆盖告警的**产生、重复发生与消除**；OMS 不设「受理/确认」概念，故无该类状态需要上报 | FR-ALM-005 |
| 告警重复发生 | 即使页面不重复展示，仍须**重复上报 SNMP**，供上层网管累计次数与刷新时间 | FR-ALM-001 |
| 告警消除 | 须上报消除信息，使上层网管可关闭对应告警 | FR-ALM-005 |
| 上报开关关闭 | 不执行上报，告警仅在 OMS 内展示 | FR-ALM-002 |
| 告警已被屏蔽 | 不执行上报 | FR-ALM-003 |
| 上报开关已开启但 SNMP 上报通道未配置或未启用 | 提示管理员先完成通道配置与启用，完成前不进行上报 | FR-3RD-001 |
| 上报失败 | 由 M14 的上报通道按策略重试；持续失败则产生告警并保留待处理记录 | FR-3RD-001 |
| 上报目标不可达 | 由 M14 标记上报通道不可用并保留待上报内容，恢复后不重复上报已成功的内容 | FR-3RD-001 |
| 上报动作 | 留痕，可供查询与审计 | 无 |

**待确认**

无

### 3.5 FR-ALM-005 告警消除

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-ALM-005 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望告警能在产生它的模块报告异常恢复时自动消除、也能由我手动消除，并且已消除的告警展示在历史告警中，以便告警列表只保留仍需关注的异常，同时保留可追溯的消除记录。

**③ 前置条件与触发方式**

- 前置条件：告警已被接收并处于未消除状态；产生该告警的模块会在异常恢复时主动上报消除信息；手动消除时操作者具备告警消除权限
- 触发方式：事件（产生告警的模块在异常恢复时主动上报消除信息）；页面入口（运维人员手动消除）

**④ 主流程**

1. 告警处于未消除状态，展示在活动告警列表中
2. 产生该告警的模块在异常恢复后主动上报消除信息
3. 系统据此将该告警自动置为已消除，并记录消除来源、消除时间与依据
4. 运维人员也可在告警详情中手动消除告警，并填写消除说明
5. 消除后的告警从活动告警列表移出，转入历史告警视图
6. 已消除的告警仍可按时间、来源与级别查询与追溯
7. 已消除的告警再次出现时，按新告警重新生成，不并入历史记录

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 产生告警的模块上报异常恢复 | 由系统自动将对应告警置为已消除，无需人工干预，并记录消除来源、时间与依据；无法匹配到活动告警的消除信息须记录并提示 | FR-ALM-001 |
| 各模块的消除上报义务 | 任何产生告警的模块（含跨模块的 M07 License 管理等）在其异常恢复后，须主动向本模块上报消除信息 | FR-ALM-001 |
| 来源未上报消除信息 | 告警保持未消除，**不得自动消失或按超时静默消除**；由运维人员核实后手动消除 | 无 |
| 运维人员手动消除 | 允许手动消除并填写消除说明；消除动作留痕，可供审计 | 无 |
| 已消除的告警 | 转入历史告警视图，**不参与重复判定**，不再计入活动告警统计 | FR-ALM-002 |
| 已消除的告警再次出现 | 视为新告警重新生成并从零累计，不并入已消除的历史告警 | FR-ALM-001 |
| 消除动作 | 全程留痕，记录消除方式（自动 / 手动）、时间与操作者或来源 | 无 |
| 告警消除后的对外同步 | 按上报范围上报消除信息，使上层网管同步关闭对应告警 | FR-ALM-004 |
| 操作者无告警消除权限 | 拒绝消除并提示 | FR-PERM-001 |
