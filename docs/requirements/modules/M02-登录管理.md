## 1. 模块概述

登录管理是 OMS 的身份认证与会话管理模块，负责确认访问者身份并在认证通过后维持其可用会话。本模块解决「谁能进入 OMS、进入后能维持多久、异常会话如何处置」的问题，是 OMS 一切功能与权限判定的入口。模块依据 M01 账户管理提供的账户状态决定能否认证，依据 M15 安全策略管理提供的密码策略与会话策略决定认证强度与会话生命周期。认证成功后建立的本地会话是 M05 SSO Server 提供单点登录、M16 权限控制进行权限判定的基础。本模块只负责 OMS 本地登录认证与本地会话，不涉及外部认证系统对接，也不涉及单点登出（SLO）——SLO 属单点登录场景，由 SSO 分册承担。

| 项 | 内容 |
| --- | --- |
| 模块定位 | OMS 统一身份认证与会话生命周期管理，是所有功能访问的可信入口 |
| 上游依赖 | M01 账户管理提供账户状态与账户归属，决定能否认证；M15 安全策略管理提供密码策略与会话策略（登录失败处理、会话超时时长、并发会话数） |
| 下游影响 | M05 SSO Server 以本地会话为基础提供单点登录；M16 权限控制依据会话身份给出权限判定结果 |
| 关键外部系统 | 无 |

### 3.1 FR-AUTH-001 账号登录/密码认证

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-AUTH-001 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望使用账户与密码登录 OMS，以便在通过身份确认后访问被授权的功能与数据。

**③ 前置条件与触发方式**

- 前置条件：账户已在 M01 创建且状态允许登录；账户已设置可用的登录密码；密码策略与会话策略已由 M15 配置并生效
- 触发方式：页面入口（登录页面）

**④ 主流程**

1. 用户在登录页面输入账户标识与登录密码
2. 系统校验该账户是否存在且当前状态允许登录
3. 系统按密码策略校验密码是否正确
4. 系统判定本次登录是否触发验证码要求，必要时要求并校验验证码
5. 系统判定该账户是否属于首次登录，必要时转入强制修改密码流程
6. 认证通过，系统建立会话并签发访问凭据
7. 系统记录本次认证结果并跳转至该用户可访问的功能首页

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 账户不存在或状态为禁用 | 拒绝登录并给出统一提示，不暴露账户是否存在 | FR-ACC-001 |
| 登录密码错误 | 拒绝登录，累计该账户的连续登录失败次数 | FR-SEC-003 |
| 连续登录失败次数达到策略阈值 | 按策略锁定账户或延长限制时间，并对后续登录强制启用验证码 | FR-SEC-003 |
| 账户处于锁定或冻结状态 | 拒绝登录，并提示按策略稍后重试或联系管理员 | FR-ACC-001 |
| 密码已超过策略规定的有效期 | 拒绝登录并引导用户完成密码修改 | FR-SEC-002 |
| 登录发生在策略禁止的时段或来源 | 拒绝登录 | FR-SEC-003 |
| 账户为首次登录且需修改初始密码 | 认证通过但不授予其他功能访问，转入强制修改密码流程 | FR-AUTH-006 |
| 登录成功后 | 重置该账户的连续登录失败次数 | FR-SEC-003 |

**待确认**

无

### 3.2 FR-AUTH-002 JWT token 生成与解析

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-AUTH-002 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望登录成功后由 OMS 签发访问凭据，并在后续访问中由系统自动识别与校验该凭据，以便无需重复输入账号密码即可持续访问，且凭据被篡改或已过期时无法继续访问。

**③ 前置条件与触发方式**

- 前置条件：账户认证已通过且会话已建立；凭据签发与校验所需的安全参数已由安全策略配置生效；系统与访问方时间处于允许偏差范围内
- 触发方式：事件（认证成功后自动签发凭据）；事件（后续每次访问时自动解析与校验凭据）

**④ 主流程**

1. 用户认证通过，系统为其建立会话
2. 系统为本次会话签发访问凭据并交付访问方
3. 用户携带该凭据访问 OMS 功能
4. 系统解析该凭据并校验其有效性与完整性
5. 校验通过时，系统在会话有效期内允许本次访问
6. 凭据临近过期或已过期时，系统按会话续期规则处理
7. 凭据被拒绝时，系统终止本次访问并清除已失效凭据

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 访问时未携带凭据 | 拒绝访问并引导用户重新登录 | 无 |
| 凭据被篡改或无法解析 | 拒绝访问，并使该凭据立即失效 | 无 |
| 凭据已过期 | 拒绝访问，按会话过期与续期规则处理 | FR-AUTH-003 |
| 凭据对应的会话已被登出或被剔除 | 拒绝访问 | FR-AUTH-004 |
| 凭据使用场景超出策略允许范围 | 按策略拒绝访问或要求重新认证 | FR-SEC-003 |
| 凭据所属账户在有效期内被禁用 | 拒绝访问并使该凭据失效 | FR-ACC-001 |

**待确认**

无

### 3.3 FR-AUTH-003 会话过期与续期

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-AUTH-003 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望会话在长时间无操作后自动过期、在持续操作时自动续期，以便在连续使用不被打断的同时避免会话被长期占用。

**③ 前置条件与触发方式**

- 前置条件：用户已登录并持有有效会话；会话超时时长、最大会话时长与并发会话数已由 M15 配置生效；系统具备统一的会话时间基准
- 触发方式：定时任务（会话有效性巡检）；事件（用户操作触发续期判定）

**④ 主流程**

1. 用户登录成功，系统按会话策略设定本次会话的有效期
2. 用户操作期间，系统持续更新该会话的最近活动时间
3. 系统按策略判定会话是否空闲达到超时阈值
4. 未达超时阈值且满足续期条件时，系统延长会话有效期
5. 会话空闲达到超时阈值或达到最大会话时长时，系统使其失效
6. 会话失效后，系统终止该会话并要求用户重新认证

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 会话空闲时长达到策略超时阈值 | 会话失效，后续访问要求重新登录 | FR-SEC-003 |
| 会话已到期 | 直接进入过期失效处理，不提供宽限期内的无感续期 | FR-SEC-003 |
| 用户在会话临近过期时继续操作 | 在策略允许范围内自动续期，不打断当前操作 | FR-SEC-003 |
| 会话已过期仍发起访问 | 拒绝访问并引导重新登录 | FR-AUTH-002 |
| 续期后累计时长超过策略允许的最大会话时长 | 不再续期，要求用户重新认证 | FR-SEC-003 |
| 同一账户的会话数超过策略上限（并发上限，或按会话数量判定的异地/多端登录限制） | **拒绝新登录**并向用户给出可理解的原因；既有会话保持可用，不被终止 | FR-SEC-003 |
| 会话所属账户被禁用或被删除 | 立即终止该账户的全部会话 | FR-ACC-001 |
| 授权关系变更（角色绑定、用户组成员、资源组关联等） | 立即将**受影响的已登录用户**的会话置为过期，强制其重新登录，使最新授权口径即时生效；未受影响的在线用户会话不受影响 | FR-PERM-001 |
| 会话巡检未完成即发生服务中断 | 恢复后按策略重新判定，超时会话仍应失效 | FR-SEC-003 |

**待确认**

无

### 3.4 FR-AUTH-004 在线用户查询与剔除

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-AUTH-004 | V1.0 |

**② 需求描述**

作为系统管理员，我希望查看当前在线用户及其会话情况，并强制剔除异常或需要回收的会话，以便及时处置会话层面的问题。

**③ 前置条件与触发方式**

- 前置条件：操作者具备在线用户查看权限；执行剔除时操作者另需具备会话剔除权限
- 触发方式：页面入口（在线用户管理页面）

**④ 主流程**

1. 系统管理员进入在线用户管理页面
2. 系统展示当前在线用户及其会话概况
3. 系统管理员按条件筛选并定位目标用户或目标会话
4. 系统管理员选择目标会话并确认剔除
5. 系统校验操作者权限与操作合规性，终止目标会话
6. 系统使被剔除会话的访问凭据同步失效
7. 被剔除的会话从在线列表中移除，该用户后续访问需重新认证

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 操作者无在线用户查看权限 | 拒绝访问在线用户列表 | FR-PERM-001 |
| 操作者无会话剔除权限 | 拒绝执行剔除操作 | FR-PERM-001 |
| 未选择目标或目标会话已失效 | 提示目标不存在或已离线，操作不生效 | 无 |
| 被剔除用户再次发起访问 | 拒绝访问并要求重新登录 | FR-AUTH-002 |
| 剔除的范围 | 仅终止 OMS 本地会话，不触发上层业务客户端的单点登出 | 无 |
| 剔除执行失败 | 提示处理失败并保留原会话，允许重新发起 | 无 |
| 被剔除用户重新登录 | 允许登录，但纳入策略允许的并发会话数限制 | FR-SEC-003 |

### 3.5 FR-AUTH-005 验证码生成与校验

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-AUTH-005 | V1.0 |

**② 需求描述**

作为安全管理员，我希望系统在登录失败次数达到策略阈值后强制要求输入验证码，以便抑制针对账户的自动化口令尝试。

**③ 前置条件与触发方式**

- 前置条件：验证码能力始终启用；待登录账户或来源的连续登录失败次数达到策略阈值；用户处于登录页面
- 触发方式：页面入口（登录页面）；事件（登录失败次数达到策略阈值时触发验证码要求）

**④ 主流程**

1. 用户在登录页面提交账户与密码
2. 系统判定该账户或来源的登录失败次数是否达到策略阈值
3. 达到阈值时，系统生成验证码并展示给用户
4. 用户在有效期内输入验证码并提交
5. 系统校验验证码的有效性与正确性
6. 校验通过后，系统继续执行密码认证
7. 校验失败时，系统刷新验证码并按登录失败处理

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 登录失败次数未达到策略阈值 | 不要求验证码，直接进入密码认证 | FR-SEC-003 |
| 验证码错误 | 拒绝本次登录，刷新验证码并累计一次登录失败 | FR-SEC-003 |
| 验证码已过期 | 拒绝本次登录并提示重新获取 | 无 |
| 未输入验证码 | 拒绝本次登录 | 无 |
| 频繁要求重新获取验证码 | 按策略限制验证码获取频率 | FR-SEC-003 |
| 验证码连续多次错误 | 视为登录失败，触发策略中的账户锁定处理 | FR-SEC-003 |
| 登录成功后 | 解除对验证码的强制要求并重置失败计数，恢复为按失败次数阈值触发 | FR-SEC-003 |
| 验证码能力的启停 | 始终启用，不提供关闭或停用配置 | 无 |

**待确认**

无

### 3.6 FR-AUTH-006 首次登录强制修改密码

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-AUTH-006 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望在首次登录时被强制修改初始密码后才能使用系统，以便避免初始凭据被长期沿用带来的安全风险。

**③ 前置条件与触发方式**

- 前置条件：账户状态允许登录；账户为首次登录或初始密码尚未修改；密码策略已由 M15 配置生效
- 触发方式：事件（登录成功且判定为首次登录时触发）

**④ 主流程**

1. 用户完成账号与密码认证
2. 系统判定该账户为首次登录且需要修改初始密码
3. 系统引导用户进入修改密码流程，暂不授予其他功能访问
4. 用户输入初始密码与拟设置的新密码
5. 系统按密码策略校验新密码的合规性
6. 系统保存新密码并标记该账户首次登录已完成
7. 系统提示修改成功并要求用户使用新密码重新登录

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 首次登录认证成功 | 初始凭据立即失效，完成改密前不得使用其他功能 | FR-ACC-002 |
| 未完成改密即尝试访问其他功能 | 拒绝访问并强制返回修改密码流程 | FR-AUTH-001 |
| 新密码不满足密码策略 | 拒绝修改并指明不满足的策略项 | FR-SEC-002 |
| 新密码与初始密码或历史密码相同 | 拒绝修改 | FR-SEC-002 |
| 初始密码输入错误 | 拒绝修改并累计登录失败次数 | FR-SEC-003 |
| 改密过程中用户中断或离开 | 保持首次登录未完成状态，下次登录继续强制修改 | 无 |
| 改密过程中账户被禁用 | 终止流程并拒绝其登录 | FR-ACC-001 |
| 修改密码成功后 | 使该账户此前的会话全部失效 | FR-AUTH-003 |

**待确认**

无

### 3.7 FR-AUTH-007 会话登出

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-AUTH-007 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望在主动登出时 OMS 本地会话立即失效，以便结束本次使用、避免残留会话被他人继续使用。

**③ 前置条件与触发方式**

- 前置条件：用户已登录且持有有效会话
- 触发方式：页面入口（登出入口）；事件（会话失效时执行本地登出处理）

**④ 主流程**

1. 用户发起登出
2. 系统校验当前会话是否有效
3. 系统终止本地会话并使访问凭据失效
4. 系统清理该会话相关的临时状态
5. 系统提示登出完成，用户再次访问需重新认证

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 会话已失效时发起登出 | 提示已登出，不重复处理 | 无 |
| 登出请求被重复提交 | 按幂等方式处理，仅执行一次登出 | 无 |
| 登出处理失败 | 提示失败并保留会话原状态，允许重新发起 | 无 |

### 3.8 FR-AUTH-008 首次登录用户协议确认

**① 基本信息**

| 编号 | 目标版本 |
| --- | --- |
| FR-AUTH-008 | V1.0 |

**② 需求描述**

作为业务运维人员，我希望在首次登录时先阅读并确认用户协议，以便在明确使用条款与合规要求的前提下开始使用系统；作为安全管理员，我希望确认动作可追溯，且用户在未确认协议前无法使用任何功能。

**③ 前置条件与触发方式**

- 前置条件：账户认证已通过；该账户此前未完成过用户协议确认；若该账户命中首次登录强制修改密码要求，须已使用新密码重新登录成功；待确认的用户协议内容已配置并生效
- 触发方式：事件（首次登录并进入系统主界面时自动触发）

**④ 主流程**

1. 用户完成账号与密码认证；若该账户命中首次登录强制修改密码要求，则先完成凭据修改（FR-AUTH-006），**改密后必须使用新密码重新登录**，登录成功进入系统主界面
2. 系统判定该账户此前是否已完成用户协议确认
3. 未完成时，系统**在系统主界面（首页）上**展示用户协议窗口，窗口内呈现完整的用户协议条文，并提供「确定」与「取消」两个操作
4. 窗口展示即开始计时，「确定」在 **5 秒内不可点击**，并给出倒计时提示；满 5 秒后「确定」变为可点击
5. 用户阅读协议后点击「确定」，系统记录该账户的协议确认结果（账户、协议版本、确认时间），关闭窗口
6. 窗口关闭后，用户可正常使用其被授权的功能
7. 已完成协议确认的账户再次登录时，不再展示该窗口

**⑤ 异常与规则**

| 场景 / 规则 | 期望行为 | 规则来源 |
| --- | --- | --- |
| 尚未完成协议确认 | 不得使用任何功能；协议窗口**覆盖系统主界面**，除窗口内操作外不提供其他可操作入口，也不可经关闭窗口、按键或点击背景等方式绕过 | 无 |
| 「确定」的可点击时机 | 窗口展示后满 5 秒方可点击；5 秒内保持不可点击并给出倒计时提示，不得通过绕过页面控件的方式提前确认 | 无 |
| 倒计时期间点击「取消」 | 按取消处理，不受倒计时限制 | 无 |
| 用户点击「取消」 | 拒绝本次使用，**强制登出**该账户、终止其本地会话并返回登录页，需重新认证 | FR-AUTH-007 |
| 用户未作选择即关闭窗口或离开页面 | 视为未确认，保持未确认状态，下次登录并进入主界面时再次展示 | 无 |
| 协议确认结果 | 须留痕：记录确认账户、协议版本与确认时间，可供审计追溯 | FR-OPLOG-001 |
| 窗口展示期间会话已过期 | 按会话过期流程处理，本次确认动作不生效 | FR-AUTH-003 |
| 用户协议内容发生版本变更 | 按版本策略决定是否要求已确认过的用户重新确认（见待确认） | 无 |
| 协议条文内容为空或未配置 | 按配置缺失处理，不得因配置缺失阻断登录（见待确认） | 无 |
| 已完成确认的账户再次登录 | 不再展示协议窗口，直接进入系统 | 无 |
| 与首次登录强制修改密码（FR-AUTH-006）的先后顺序 | **先完成强制修改密码，再用新密码重新登录进入系统，最后展示用户协议窗口**；改密未完成或未重新登录时不展示协议窗口，也不授予任何功能访问 | OI-M02-004 |

**待确认**

1. **遗留问题（OI-M02-005）**：用户协议的正式条文、版本管理策略与多语言要求尚未确定。
   当前版本先使用示意文本；正式条文由法务/产品提供，本条不阻塞原型评审，但阻塞 FR-AUTH-008 上线。
2. 协议条文未配置时的期望行为：是放行登录并告警，还是阻断登录。

> 与 FR-AUTH-006 的先后顺序已确认：**先强制修改密码 → 用新密码重新登录 → 进入系统主界面后确认用户协议**
> （见 OI-M02-004 闭环结论）。协议窗口展示位置为**系统主界面**，不在登录页。
